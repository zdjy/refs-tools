# 领域文档约定

本项目采用 single-context 布局，业务术语共享一份根级 glossary，系统级架构决策统一存放于 `docs/decisions/`。

开发规约统一维护在[全栈架构与 AI 编码规约](coding-standards.md)，通过根级 [AGENTS.md](../../AGENTS.md) 引用，不另设 DDD 规范或重复的架构规约。本文仅约定领域文档的阅读和术语维护方式；业务词汇见[统一语言表](../../GLOSSARY.md)，业务需求及具体决策分别见 `docs/specs/` 和 `docs/decisions/`。

## 探索代码前

- 若根目录存在 `GLOSSARY.md`，阅读与当前任务相关的术语定义；文件不存在时静默继续，不要求预先创建。
- 阅读 `docs/decisions/` 中与当前工作领域相关的 ADR。该目录是本仓库既有的 ADR 位置。
- 本项目同时使用 `docs/specs/` 存放产品和技术规格；实施功能时阅读相关规格及其关联决策。

## 术语使用

在 issue 标题、重构提案、假设和测试名称中使用项目 glossary 定义的领域词汇，不使用其明确排除的同义词。如果所需概念尚未定义，先判断是否引入了项目未采用的术语；若确有领域缺口，在解决领域模型时补充记录。

## ADR 冲突

如果方案与现有 ADR 冲突，明确指出冲突及原因，不要静默覆盖既有决策。
