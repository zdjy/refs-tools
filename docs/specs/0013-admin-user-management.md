# FS-0013：管理端用户 CRUD

## 范围

本次补齐 FS-0002 Task 4 的平台用户管理入口。保留管理端框架登录页与导航，用现有邮箱密码、邮箱验证码 API 和 HttpOnly Cookie 替换演示身份，用户数据来自 PostgreSQL。管理端视觉遵循 FS-0010，沿用其 Tailwind 3 存量接入例外，不在本次迁移样式构建系统。

## 行为与验收

- `/system/user` 提供邮箱/显示名称关键词搜索、状态筛选、分页、详情、新增、编辑和删除；私有数据只在内存保存，接口及页面不默认缓存。
- 仅有效且邮箱已验证的平台管理员可查询或变更用户；API 同事务重读并锁定账号与平台绑定，使用现有 Casbin `platform.manage` 权限。读写均写入最小审计，失败全部回滚。
- 列表/详情只返回 ID、邮箱、显示名称、验证状态、启用状态、创建时间、版本及当前平台角色，不返回密码摘要、会话、手机号或业务档案。
- 新增填写邮箱、显示名称、初始密码；邮箱规范化并保持数据库唯一；密码遵循部署策略且复用有界 scrypt。管理员创建不等同邮箱验证，用户后续通过现有邮箱验证码流程验证。
- 编辑显示名称和启用状态，邮箱只读；版本冲突返回 409 并保留编辑输入，重新读取后再操作。停用撤销所有会话，恢复不会恢复旧会话。
- 删除为 `deleted_at` 标记并停用、撤销会话，不释放邮箱，不删除历史认证、比赛和审计；删除后不出现在管理列表，重复删除返回 404。
- 禁止编辑/删除当前操作者；禁止停用/删除当前有效平台管理员或组织所有者，先通过所属模块撤权/移交。普通用户 CRUD 不变更角色绑定，不提供自定义角色、菜单授权或批量删除。
- 加载失败区别于空结果；支持重试、离线提示、提交互斥、错误保留输入。停用与删除需确认；支持键盘、弹窗焦点恢复及局部表格横向滚动，按钮至少 44px 高。
- 保留框架登录页样式，默认密码登录，并可切换邮箱验证码登录；两种方式都不提供自助注册。发送验证码使用 `POST /auth/email-challenges` 的 `login` 用途，验证码登录调用 `POST /auth/login/email-code`，不要求账号先设置密码。
- 两种登录成功后都必须调用 `GET /admin/session` 核验平台权限，核验失败尝试注销刚建立的普通会话，不写入管理端身份或进入管理页面；验证码本身不授予平台角色。会话恢复失败跳转登录，权限不足显示明确错误；不将 Cookie 或私有用户信息写入 localStorage。历史演示 token 不参与授权。
- 验证码与当前规范化邮箱绑定，邮箱或登录方式改变后清除旧 challenge、验证码与密码；发送期间、登录期间禁止重复提交和切换。迟到响应在邮箱切换或页面销毁后不更新身份或成功反馈。
- 发送成功提供 toast 与持续的查看邮箱提示；错误验证码、过期、频控、权限不足和网络错误提供就近文本与手动重试，失败保留当前输入。离线明确未提交，网络超时提示先刷新核对结果；写操作不自动重试。服务端沿用现有有效期、发送频控与尝试次数配置，前端不另设频控数值。
- 邮箱、密码及验证码错误只在字段下方显示，并聚焦首个错误字段；非字段错误使用 `role="alert"` 并可聚焦。按钮内 loading、防重入及 `UiSubmitHint` 表达发送/登录过程。保留中英文文案、中性深浅主题、320px 无横向溢出和至少 44px 触控目标。

## 部署

- 静态管理端与 API 需同源 HTTPS 部署，API 的 `AUTH_PUBLIC_ORIGIN` 必须匹配。本地 Compose 入口为 `https://localhost:8443/admin/`，与裁判端共用同一 Origin（依据见 [ADR 0011](../decisions/0011-local-compose-environment.md) 的后续实施）。API 不接受框架演示 token，不提供匿名管理账号初始化。
- 管理端真实 API 请求统一经 `src/api/http/platform-client.ts`（alova，禁用缓存与请求合并，仅同源 Cookie），不使用框架演示的 `utils/http/alova` 实例，依据见 [ADR 0023](../decisions/0023-alova-http-client-and-ddd-gateway.md)。
- 首个平台管理员继续按 `apps/api/db/AUTHORIZATION_AUDIT.md` 受控初始化。
- 新迁移 `0005_admin_users.sql` 添加逻辑删除与版本字段；后续组织扩展迁移改用下一个空闲编号，不改写既有迁移。

## 邮箱验证码登录验证记录

- 管理端单测 21 个文件、114 个用例通过，其中新增认证网关与登录状态测试 18 个；覆盖两种登录、管理会话核验/失败清理、字段校验、过期、频控/离线/网络错误、互斥和迟到响应。
- 在 `apps/admin-web` 执行 `pnpm run type-check`、`pnpm run build` 通过，`git diff --check` 与登录页机械设计检查通过；无新增依赖、DTO、后端逻辑或迁移，数据库及事务相关自检不适用。
- JS 总产物由 3478.1 KB 增至 3484.5 KB，gzip 由 1155.0 KB 增至 1158.1 KB；沿用现有主题与工具类，未新增手写 CSS。现有体积报告未识别入口静态闭包，因此不将其 0 KB 输出作为首屏指标。
- 浏览器浅色 320px：验证码方式、获取按钮与登录按钮均可见，无页面级横向溢出，四个主要按钮均为 44px 高；1536px DOM 测量同样无溢出。输入的可访问名称、数值键盘及自动填充属性已核对。
- 使用浏览器 fetch 替身验证发送成功的持续提示，以及验证码登录 → `/admin/session` 拒绝 → 注销的调用顺序；拒绝后保留验证码、显示权限说明并聚焦 `role="alert"`，未实际调用邮件投递或使用真实账号。
- 浏览器自动化的坐标点击与原始 Enter 未可靠触发，使用 DOM click / 表单 submit 补测交互；未完成真实 SMTP/数据库端到端、完整键盘 Tab 流程、深色主题、reduced-motion 和真机验收。桌面截图超时，仅完成桌面结构/尺寸检查，移动端已查看渲染。
