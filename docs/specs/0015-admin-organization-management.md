# FS-0015：管理端组织治理首期

## 范围

推进 FS-0002 Task 7 的平台治理入口；本期交付 `/system/organization` 的真实组织查询、详情、代录申请、审核和冻结管理。视觉沿用 [FS-0010](0010-admin-color-theme.md)，继续使用管理端现有 Tailwind 3 接入例外。页面采用紧凑筛选区、可局部横向滚动的组织表格和单一详情/操作弹窗，不新增主题或装饰性指标。

成员邀请、自主入会审核及成员结束的接续实现见 [FS-0016](0016-organization-membership.md)；成员码、组织角色编辑、所有权转移和解散仍属后续 Task 7；不将本期标为完整组织模块交付。代录申请是平台为已有用户录入组织资料，不替代后续用户自助申请接口。

## 行为与验收

- 仅邮箱已验证、账号有效的当前平台管理员可读写；每个用例同事务锁定账号及平台角色并检查既有 `platform.manage`，平台治理入口不授予组织运营的超级权限。
- 列表支持名称/地区关键词、状态、分页，返回 ID、名称、地区、用途、所有者 ID、状态、创建时间和版本。详情额外返回负责人实名、联系方式、审核人/时间和最近治理理由；列表不返回联系方式与实名。
- 代录申请填写名称、地区、用途、联系方式，并按昵称或邮箱搜索、选择一位已有用户作为负责人，不手填用户 ID 或实名。候选项展示昵称和邮箱以区分同名账号，复用平台用户查询及分页；未验证邮箱的账号明确标记且不可选，查询失败显示重试，搜索旧响应不得覆盖当前结果。目标用户须有效且邮箱已验证，提交时由 API 实时复核。创建一律为 `pending_review`，没有成员关系和组织角色。
- 创建载荷只含组织资料、联系方式和所选 `ownerUserId`，拒绝手填 `ownerLegalName`。现阶段用户账号没有可读取的实名档案，不用昵称冒充实名；新申请的历史实名列沿用空值默认，已有实名数据及受保护详情投影保留。
- 审核仅允许 `pending_review → active/rejected`；通过时再次验证所有者账号，并在同一事务建立/激活其成员关系及 `owner`、`organizer` 默认绑定。拒绝不得产生运营授权。历史角色冲突应明确失败并回滚，不覆盖其他绑定。
- 冻结仅允许 `active → frozen`，解冻仅允许 `frozen → active`；不删除成员、绑定或历史业务数据。已有实时 scope 授权负责在冻结后阻止新运营，解冻后仍逐次判断绑定和成员现状。解冻须重新验证所有者账号及当前所有者成员/角色依据，不恢复已撤销绑定。
- 审核通过、驳回、冻结、解冻均填写 1–500 字理由并二次确认，理由提示不得包含凭据或 URL；所有写入带 `expectedVersion`，过期表单或非法状态转换返回 409。失败保留输入，重新读取后再操作。
- 查询、代录、审核、冻结和解冻均追加审计；组织写入与授权/成员变化、审计共用连接并原子提交。审计快照仅含状态、版本、所有者 ID，不保存实名或联系方式；治理理由遵守既有审计安全校验。
- 真实 API 使用 `/api/v1/admin/organizations`（GET/POST）、`/{id}`（GET）、`/{id}/decision`（POST）。Cookie/Origin 门禁、`no-store` 与现有管理端一致。拒绝额外角色/状态字段；ID 与参数由 contracts Schema 校验。
- 页面区分加载、失败、空列表与陈旧数据，支持重试、离线提示和提交互斥；私有信息只在内存中保存。弹窗支持键盘、焦点恢复，触控操作至少 44px，320px 无页面级溢出，检查 Light/Dark 与 reduced-motion。

## 持久化与兼容

- 新增 `0006_organizations.sql`，扩展既有组织骨架，不改写历史迁移。旧骨架行补名称“未命名组织”及空业务字段；后续业务写入要求完整资料。旧测试与归属骨架仍可使用默认字段，不凭迁移自动授予角色。
- 组织字段与成员关系归 organizations 模块，角色写入复用 authorization 端口，用户有效性通过身份模块的只读锁定端口检查；不跨模块直接写用户或角色表。
- 新增版本与查询索引；状态更新采用行锁及版本条件更新，当前成员唯一索引与角色唯一索引继续兜底。事务内先锁组织、再检查所有者和写入成员/角色，避免冻结与组织运营之间陈旧授权。

## 交付自检（对应 workflow 清单顺序）

1. 业务 SQL 仅在 Repository；路由和 Service 无 SQL。
2. Repository/事务端口无驱动类型，Service 由入口装配。
3. 变更、成员/角色和审计共用事务连接，无外部 IO；现有事务测试及真实回滚测试通过。
4. 组织/成员归属明确，参数化查询、版本、唯一约束、行锁与真实迁移检查通过。
5. 新增 Vue 文件均小于 230 行。
6. Vue 和 Composable 无直接 HTTP 请求。
7. 新网关经现有无缓存客户端，翻译为组织上下文错误；不涉及对象直传。
8. 所有跨端载荷在 contracts。
9. 新增纯状态规则和 Service 均有 Vitest 测试。
10. 复用现有 Casbin 端口与固定策略，无角色/决策缓存；实时撤权与同事务审计通过测试。
11. Naive UI 仅用于表现层，未进入网关、Composable 或 domain。
12. 业务组件只属于组织页面，无跨页面引用或无用通用包装。
13. 主题沿用管理端 FS-0010，无页面配色或逐页 token。
14. 交互校验、domain 状态和 API 授权分离；失败保留输入，离线/重试/提交互斥与确认已实现。
15. 状态限页面 Composable，无新增 Pinia 或隐式持久化。
16. Router 只增加静态路由，无新增领域守卫。
17. 桌面/320px、键盘、触控、主题、减弱动态及构建已检查；完整屏幕阅读器专项、其他移动浏览器与总内存峰值未执行。

19. 纯状态转换 JSDoc 说明非法边界；并发成员 SQL 有说明，契约版本为 expectedVersion。
20. 布局使用 Tailwind；沿用管理端 Tailwind 3 例外，集中 reduced-motion CSS 为框架容器适配。
