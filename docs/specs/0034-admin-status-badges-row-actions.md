# FS-0034：管理端状态标签、行内操作与导航折叠

- 状态：已实施，验证记录见 §7。
- 适用应用：`apps/admin-web`。无后端、DTO、授权或迁移变更。
- 依据：[FS-0010 管理端 UI 基线](0010-admin-color-theme.md)（颜色、密度与弹窗约定）、[前端规约](../agents/coding-standards/frontend.md)（分层、操作反馈、行数上限）。
- 覆盖页面：用户、组织（含成员与平台邀请码弹窗）、认证、文件。

## 1. 目标与非目标

目标：让列表状态一眼可辨、把破坏性入口从编辑/查看弹窗里拿回列表行、让左侧导航可折叠并记住选择、按输入方式给出合适的行内操作与列表形态（PC 表格 + 纯图标按钮，移动端卡片 + 文字按钮）。

非目标：不改动业务规则、权限、后端契约与 `uiPalette.ts` / `uiScale.ts` 的 token 取值；不新增色相；不重做 Mock 页（菜单权限、角色权限）的模板布局。

## 2. 状态标签

统一由 `AdminBadge` 渲染，语义分两层：

| 维度 | 取值 | 含义 |
| --- | --- | --- |
| `tone` | `success` | 正常、可用、生效中 |
| | `warning` | 待审核、待上传、进行中 |
| | `danger` | 已驳回、已冻结、核验拒绝 |
| | `neutral` | 已停用、已使用 |
| `variant` | `solid`（默认） | 当前生效、需要关注 |
| | `outline`（虚线） | 终态或等待对方处理（已解散、已过期、已删除、已撤销、需补件） |

- 标签 20px 高、4px 圆角、12px/500，含 6px 语义色圆点，**始终带文字**，不只用颜色表达状态。
- 同一列表内每个状态的颜色与样式组合都不重复；两种状态若同色，用 `variant` 区分（如已驳回=红虚线、已冻结=红实底）。
- 各列表映射：

| 列表 | 状态 → 标签 |
| --- | --- |
| 用户 | 正常=success；已停用=neutral |
| 用户·邮箱验证 | 已验证=neutral；未验证=warning |
| 组织 | 待审核=warning；正常运营=success；已冻结=danger；已驳回=danger+outline；已解散=neutral+outline |
| 文件 | 待上传=warning；可用=success；核验拒绝=danger；已过期=warning+outline；已删除=neutral+outline |
| 成员 / 邀请 | 正式成员·已接受=success；待处理=warning；已驳回=danger；已拒绝=danger+outline；已移除=neutral；已退出·已撤销·已过期=neutral+outline |
| 平台邀请码 | 可使用=success；已使用=neutral；已过期=warning+outline；已撤销=neutral+outline |
| 认证 | 审核中=warning；需补件=warning+outline；已批准=success；已驳回=danger；已暂停=danger+outline；草稿·已撤销=neutral+outline |

- 认证队列条目的状态与详情页标题下的状态（含「当前效力」）同样使用标签，不再只显示纯文本。
- 实现位置：`components/admin-shell/AdminBadge.vue`（样式与无障碍）、`badge.ts`（类型）、`status-badge.ts`（表格渲染助手），各页面 `*.presentation.ts` 只维护状态映射。

## 3. 行内操作与窄屏卡片

### 3.1 动作描述与渲染分离

- 表格与卡片共用同一份动作描述 `RecordAction`（`components/admin-shell/record-card.ts`）：
  `action` 为普通动作，`confirm` 表示破坏性动作（就地确认气泡）。
- 每个页面的 `*.presentation.ts` 提供 `xxxActions(row, options)`，再由 `actionNode()` 渲染成表格按钮，
  或原样交给卡片渲染，避免同一动作在两种形态里各写一遍。
- 图标、危险色、禁用条件只在一处定义（例如「移交」只对 active / frozen 出现、「删除」对本人与留存证据禁用）。

### 3.2 PC（>767px 且非触屏）

- 表格保留多列投影；操作列只显示图标，操作名称由 `title` 悬浮提示与 `aria-label` 提供（与 `AdminIconButton` 一致的原生提示约定）。
- 动作列宽度按纯图标计算（每个动作约 28px），宽屏不会因文字挤压其他列。
- 行内操作默认 `opacity: 0`，行悬停、行聚焦或选中时显现，但始终在 Tab 顺序内。

### 3.3 移动端 / 触屏（≤767px 或 `pointer: coarse`）

- **列表形态改为卡片**：`AdminDataTable` 在窄屏且传入 `cards` 时渲染 `AdminRecordList`，
  表格不再横向滚动。
- 卡片结构：标题（可点击进入详情）+ 右侧状态标签 + **具名字段**（每行「字段名 + 值」，名称左对齐 64px，值用 ink 色）+ 底部操作行。字段不带名称时用户无法判断值的含义，因此 `AdminRecordCard.fields` 强制 `{ label, value }`。
- 卡片底部操作始终是**图标 + 文字**，高度 44px：触屏没有 hover，文字必须常显，不能只靠 tooltip。
- 字段优先级由各页面 `xxxCards(rows, options)` 决定，不追求把表格所有列塞进卡片。
- 分页、空态与加载提示仍由 `AdminDataTable` 统一承载（卡片形态下外壳不再画第二层边框与阴影）；
  空态文案与分页参数沿用页面原有取值。
- 弹窗内的成员 / 邀请表同样接入 `cards`：成员卡片只有「成员名 + 状态标签 + 申请/加入时间 + 动作」，邀请卡片只有「受邀人 + 状态标签 + 过期时间 + 撤销」；用户 ID 等技术字段不上卡片（留在桌面表格与详情里）。
- 判定标准：窄屏一律卡片（统一交互范式），**字段按页面取量**（只放支持本页决策的字段）。需要跨行对齐比较同一列数值的表格（成绩、批量核对）才保留表格，本项目当前没有这类页面。

### 3.4 窄屏下仍以表格出现时的处理

- 未提供 `cards` 的表格在窄屏仍按表格渲染，操作按钮显示图标 + 文字，命中区 44×44 CSS px；`aria-label` 保持可访问名称。
- 列宽由 `actionColumnWidth(labels, compact)` 计算：宽屏按图标、窄屏按文字估算，避免为看不见的文字留白。
- 破坏性动作沿用 `AdminConfirmButton` 的就地确认气泡：气泡打开后焦点进入气泡并锁在气泡内，
  Esc 先关气泡并把焦点交回触发按钮。

## 4. 破坏性入口不再放进弹窗

| 场景 | 旧行为 | 现行为 |
| --- | --- | --- |
| 删除用户 | 用户编辑弹窗页脚左侧「删除用户」 | 列表行内「删除」+ 就地确认；失败写在页面横幅，成功 toast 提示 |
| 删除文件 | 文件详情弹窗页脚左侧「删除文件」 | 列表行内「删除」打开独立删除弹窗（理由必填 + 二次确认），详情弹窗只保留「授权下载」「关闭」 |
| 停用用户 | 编辑弹窗内就地确认 | 不变（属于状态变更，不是删除） |
| 组织治理（驳回/冻结/解冻） | 详情弹窗页脚 | 不变（依赖弹窗内的理由字段，属于审核决定） |

- 用户删除不再要求先打开弹窗：`useUsers.remove(user)` 直接用行数据与版本号提交；本人账号仍禁用入口。
- 文件删除因服务端要求理由并写审计，采用独立单步确认弹窗（`FileDeleteDialog.vue`）；这是 §3 就地确认规则的窄范围例外，理由是理由输入需要完整表单空间。
- 用户详情弹窗不再接收 `actorId` 与 `remove` 事件，页脚只剩「关闭」与（编辑态）「保存」。

## 5. 左侧导航折叠

- 折叠状态由 `useDesignSettingStore().siderCollapsed` 单一持有，持久化在 `localStorage` 的 `UI-SIDER-COLLAPSED`，顶栏箭头、侧栏底部入口与「界面设置」抽屉开关共享同一状态。
- 侧栏底部新增折叠入口 `AdminSiderCollapse.vue`：展开态显示「收起侧栏」文字 + 左箭头，收起态只留图标并带 tooltip；`aria-pressed` 表达状态。
- 侧栏改为 `position: sticky` + `height: calc(100dvh - 顶栏高度)`：折叠入口固定可见，不随长列表滚到文档末尾。
- 收起态条目只显示图标、居中，鼠标悬停显示右侧 tooltip；窄屏侧栏仍是抽屉（顶栏汉堡按钮开关，遮罩点击关闭），底部折叠入口在抽屉中隐藏。
- 折叠标签不再用 `:global()` 选择器（Vue 3 的作用域 CSS 不生成这类规则），改为组件内 `is-collapsed` 类，修掉收起后图标被文字撑开、侧栏出现横向滚动的问题。

## 6. 顺带修复

- `AdminFilterBar` 增加 `align-content: flex-start`：窄屏换行后不再被拉伸出的空行撑高。
- `AdminField` 的 `fixed` 宽度改用 CSS 变量 `--admin-field-width` 承载：原先内联 `flex: 0 0 148px` 在窄屏竖向布局里会变成 148px 高度，筛选区出现大片空白。
- 删除文件成功后若详情弹窗正指向该文件，同步刷新详情；删除失败保留理由与目标，提示「访问可能已撤销」。
- 成员 / 邀请表的用户 ID 列由 260px 收窄到 220px 并启用 tooltip 省略：720px 弹窗内所有列（含操作列）完整可见，不再被裁掉。
- 「代录组织申请」弹窗的单行输入框恢复整宽：字段循环里给所有 `NInput` 都传了 `autosize`，而 Naive UI 会因此加上 `n-input--autosize`，使单行输入框退化为按内容收缩（实测宽度 27px）。现在只有「组织用途」textarea 带 `autosize`，其余单行输入框走默认分支。

## 7. 验证记录

工程检查：

- `npx vue-tsc --noEmit`：无错误。
- `npx vite build`：通过（约 19–38s）。
- `pnpm vitest run apps/admin-web`：21 个文件 122 个测试通过；`users-state`、`files-state` 已按新的行内删除流程重写用例（离线不提交、失败不报成功、提交互斥、失败保留理由与目标）。

浏览器（Chrome，真实登录态与本地 API，1366×647 / 1440×800 / 390×844，浅色与深色）：

- 用户页（1440/1536）：邮箱验证与账号状态均为彩色标签（已验证中性、未验证黄、正常绿、已停用灰）；操作列为纯图标（24px），带 `title`/`aria-label`，删除为危险色；删除气泡向右下展开并停在表格卡内。
- 用户详情弹窗页脚只剩「关闭」，不再出现删除入口。
- 组织页：正常运营绿、已驳回红虚线、已解散灰虚线；操作列固定在右侧，1440px 无横向滚动。
- 文件页：状态标签「可用」绿；行内「详情/移除前的删除」图标 + 文字，认证证据类文件的删除入口禁用；点击删除打开独立「删除文件」弹窗（理由必填、取消/确认删除）。
- 侧栏：底部「收起侧栏」固定在视口内，收起后 56px 只显示居中图标、无横向滚动，再次点击恢复并把状态写入 `UI-SIDER-COLLAPSED`。
- 成员管理弹窗（390px）：成员列表切换为卡片（成员名 + 正式成员 + 加入时间）；桌面 1440px 仍为表格且五列全部在弹窗内可见。
- 平台邀请码弹窗：实测生成一个 3 天有效的邀请码后，390px 为卡片（邀请码 …qNtg + 可使用 + 创建/过期/使用情况 + 撤销），点「撤销」在原位弹出「取消 / 确认撤销」气泡且不超出视口；1440px 为表格（5 列 + 操作），不横向滚动。
- 实测发现并修复：`PlatformInvites.vue` 漏传 `:cards`，导致窄屏仍渲染表格；深色主题下卡片字段名（body 色）与值（ink 色）对比度正常，首次截图偏暗是主题切换过渡帧，非样式缺陷。
- 390px：用户 / 组织 / 文件三页均切换为卡片列表——用户卡片为「显示名称 + 正常/已验证 + 邮箱 + 普通用户·时间 + 详情/编辑/删除」，组织卡片为「名称 + 状态标签 + 地区·用途 + 时间 + 详情/成员（已解散无移交）」，文件卡片为「文件名 + 可用 + 用途·类型 + 大小·归属·时间 + 详情/删除（留存证据禁用）」；无横向滚动，操作按钮 44px 且带文字，本人员工卡片上的编辑/删除为禁用态；筛选区字段纵向排列无空行；侧栏为抽屉并显示文字标签。

## 8. 未覆盖项

- 认证页本地库无认证记录，状态标签只在代码与用户/组织/文件等价路径上验证，未在浏览器中看到认证队列与认证详情的实际标签。
- 冻结/停用等状态变更类破坏性动作仍在弹窗内就地确认；认证队列与认证详情的状态标签因本地无认证记录仍未在浏览器中看到实际渲染。
- 收起态 tooltip 的悬停停留时间、深色主题下气泡与危险按钮的实际截图、系统 reduced-motion 均未逐项核对。
- 1366px 宽度下用户与文件表仍有表格内横向滚动（操作列固定可见）；如需在 1366px 完全无滚动，需要进一步裁剪次要列或调整列宽策略。
- Mock 页（菜单权限、角色权限）的删除入口仍在编辑面板页脚，未迁移到列表行；该页是明确标注的 Mock 数据，仅演示确认流程。
