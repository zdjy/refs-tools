## 1. 目标与交付分层

第一期验证两个正式业务闭环：

1. **学习与考试**：资料浏览 → 练习/错题 → 正式考试 → 人工阅卷 → 成绩汇总。
2. **认证资质**：组织创建/审核 → 组织内认证 → 平台认证申请 → 独立人工复核 → 认证档案与申诉。

赛事选派、赛后履职、离线裁判工具和论坛作为可用 Beta 发布。Beta 对已登录用户开放，但不承诺与正式模块相同的稳定性；仍必须执行权限、隐私、审计和媒体安全约束。

### 1.1 明确不进入 MVP

- 私信、赛事群聊和即时通信。
- 支付、订阅、订单、优惠和收费内容闭环。
- AI 推荐、AI 自动阅卷，以及替裁判作最终规则裁决。
- 第三方赛事系统、计分牌、设备或硬件 API 集成。
- 服务端视频转码；平台只接收预处理且在允许格式内的成品视频。

## 2. 账号、登录与身份展示

### 2.1 首发登录

- MVP 首发采用邮箱验证码登录；短信验证码后置，不阻塞上线。
- 用户可在首次或后续登录时设置可选密码；设置后可使用“邮箱验证码”或“邮箱 + 密码”二选一登录。
- 新用户通过邮箱验证码注册并进入 `/account` 后，邮箱已验证且尚无密码时，直接输入并确认首次密码，无需再次获取验证码；保存成功显示注册完成。验证码校验成功时账号与会话已经建立，密码仍为可选登录方式，离开页面不删除账号。
- 首次设置资格由服务端当前邮箱验证状态与是否已有密码决定，刷新页面或后续验证码登录后仍可继续；已有密码的更换必须重新验证本人邮箱。密码保存失败保留输入供重试，成功后清空密码输入并轮换会话。
- 一个用户账号可以绑定手机号和邮箱，但首发登录实现以已验证邮箱为主；手机号能力作为后续扩展。已绑定凭据必须归属于同一用户。
- 发现手机号/邮箱已属于其他账号时，不自动覆盖或合并；进入人工合并流程，必须保留两个账号的认证、考试和审计归属。
- 邮箱必须完成验证。验证码需要有效期、发送频率限制和尝试次数限制；具体数值属于部署配置。
- 未验证邮箱可以浏览登录后的基础公共页面和资料目录；正式考试、认证、组织、论坛发帖等核心操作必须先完成邮箱验证。

### 2.2 前台身份与隐私

- 论坛和候选人列表默认展示昵称、头像和认证徽章/级别摘要。
- 实名仅在本人、对应审核范围的审核员、或获得授权的组织业务流程中可见。
- 认证证书原件、证书字段、审核附件、考试答卷图片、赛后相机原图均属于受保护资源，不因徽章展示而公开。

## 3. MVP 角色与权限矩阵

权限采用“用户 + 权限 + 资源 + 作用域 + 当前状态”判断；默认拒绝。组织、赛事、比赛、认证和媒体数据均由 API 做对象级授权，不能依赖隐藏前端按钮。

### 3.1 平台级角色

| 角色 | 主要范围 | 允许操作 | 明确禁止/限制 |
| --- | --- | --- | --- |
| 平台管理员 | platform | 审核/冻结组织；审核平台认证；处理平台级认证申诉；管理平台配置、媒体策略和账号；下线错误内容；抽查/改判考试成绩；处理组织所有权转移和解散/冻结 | 所有敏感读取和写入必须审计；不因管理员身份自动伪装成组织者或裁判长 |
| 内容编辑 | platform-content | 创建、编辑、发布、下线和修订学习资料、题目、考试；配置内容媒体；执行考试完整性校验 | 不负责认证、阅卷、论坛处罚或账号权限，除非另有独立绑定 |
| 平台阅卷员 | platform-grading | 查看授权考试的主观题答卷；按题目满分和评分说明打分、写评语；提交评分 | 不能改变题目、考试公式、认证和组织角色 |
| 平台版主/审核员 | platform-moderation | 处理帖子举报；隐藏/恢复内容；禁言/封禁；处理申诉；维护关键词和频控规则 | 不因社区治理权限获得认证原件、组织业务或考试答卷权限 |

同一账号可兼任多个平台角色，但每项高风险操作按实际权限分别审计。

### 3.2 组织与个人角色

| 角色 | 作用域 | 主要操作 | 限制 |
| --- | --- | --- | --- |
| 注册裁判 | self | 浏览资料；练习；管理收藏/最近访问；提交认证申请；加入组织；响应选派；查看自身考试和记录 | 不能访问他人私密资料，不能审核认证或管理组织 |
| 组织所有者 | organization | 维护组织；审核/移交/冻结相关组织事务；授予组织者、裁判长、组织认证员；参与组织运营 | 不能修改平台权限；兼任认证员时不得审核本人申请 |
| 组织者 | organization/event | 创建赛事/比赛；发布岗位；人工选择本组织成员；发起替换；查看必要的候选人资料；审核赛后主记录 | 不能查看不必要的证书原件；不能改变平台认证；越过岗位认证提示必须填写理由并二次确认 |
| 组织认证员 | organization | 审核本组织成员的组织内认证；核对证书字段、私有原件和执裁履历；写审核结论/备注 | 认证仅本组织有效；权限撤销后不能新审；禁止审核本人申请；不能审核平台认证 |
| 裁判长 | event/match | 在被绑定的赛事/比赛范围内处理履职、替换、签到接管、赛后记录接管和异常 | 必须绑定到赛事或比赛；不能获得组织全量管理权限 |
| 已认证裁判 | self + certification scope | 展示认证徽章；作为岗位资格提示依据；使用认证相关功能 | 认证级别不自动排序、不自动升级权限；认证结果不等同于组织管理权限 |

### 3.3 认证级别

- 支持国家级、一级、二级、三级字段。
- MVP **不对级别排序**，不自动推断“更高/更低”。级别用于展示、筛选和审核记录。
- 岗位首发只配置认证范围（平台认证/组织认证）和人数，不配置最低级别门槛。
- 认证结果必须有明确作用域：平台认证可跨组织使用；组织认证仅在签发组织内使用。

## 4. 组织与成员治理

### 4.1 组织创建

- 用户可以自助提交组织创建申请，填写组织名称、地区与用途；负责人实名及联系方式不手填，取自申请人的账号资料（真实姓名、手机号），资料不完整时不能提交。
- 平台审核通过前，组织没有任何可运营权限：不能发布赛事、选派、审核认证或授予组织角色。
- 平台一次性、短期有效的邀请码可以直接通过组织创建审核；平台创建组织邀请码与组织成员邀请码完全分离，不能跨用途使用。
- 审核通过后，创建者默认获得“组织所有者 + 组织者”。
- 组织所有者可授予组织者、裁判长和组织认证员；裁判长仍必须绑定到具体赛事/比赛。

### 4.2 入会

- 组织邀请：接受后立即成为成员。
- 组织成员邀请码：用于加入已审核组织，不能授予任何角色；支持一次性、有效期、组织绑定、使用次数限制、撤销和审计。
- 裁判自主申请：进入待审核状态，必须由组织确认后成为正式成员。
- 赛事候选人必须是所属组织正式成员；平台认证不绕过组织成员边界。
- 组织可以同时拥有多个成员，裁判也可以加入多个组织。

### 4.3 成员退出、移除与组织冻结

- 成员退出/被移除后，组织角色和当前组织权限立即失效，历史认证、选派和审计记录保留。
- 组织认证暂停，不可用于该组织的新选派；已接受但未完成的岗位冻结，由组织者/裁判长人工替换。
- 之后重新加入同一组织时，未被撤销的原组织认证自动恢复可用。
- 组织所有者、认证员或裁判长权限被撤销后，新请求立即拒绝；已成功提交的结果保留并审计。
- 平台冻结组织后，禁止新入会、认证、赛事和选派；历史数据只读保留。冻结不自动抹除历史业务记录。
- 组织所有权转移、冻结和解散由平台管理员处理并审计。
- 组织所有权转移有两条路径，均审计：平台管理员可直接移交（含冻结组织）；现任负责人也可向本组织正式成员发起，接收人接受后生效。冻结和解散仍由平台管理员处理。实现见 [FS-0028](0028-platform-invites-and-ownership-transfer.md)。

## 5. 学习资料库

### 5.1 内容范围

首发支持图文、图片、文档/PDF、音频和视频等内容。公共学习资料对登录用户可见，不按裁判级别做访问隔离；未验证邮箱的用户可以浏览公共资料目录和内容，但不能执行需要已验证身份的核心操作。认证证书等个人隐私材料不属于公共资料库。

- 内容编辑可直接创建、发布和下线资料，不设二次发布审批。
- 发布前执行字段完整性、媒体对象状态、类型和大小校验；发布即对符合权限的登录用户可见。
- 发现错误时，编辑或管理员下线当前版本并创建新版本；已引用的历史考试/答卷继续引用原快照。
- 学习资料是否允许下载由资料配置决定；在线查看或下载都必须通过受控的短时访问授权。
- PWA 首发仅缓存目录、封面和最近访问摘要；收藏、错题本、考试历史等个人数据以服务端为准，正文、私有媒体、签名 URL 和认证原件不进入默认持久缓存。
- MVP 不记录“学习完成进度”；支持收藏和最近访问。

### 5.2 分类

- 分类树由管理员创建和维护，最多三级。
- 一份资料允许挂载多个分类。
- 普通用户和组织不能创建公共分类。
- 分类停用或删除时，资料历史引用保留；无有效分类的资料进入“未分类”处理，不物理破坏历史版本。

### 5.3 媒体策略

媒体策略由后台配置，系统提供以下保守首发默认值，可在部署前或后台按供应商能力调整：

| 类型 | 默认限制 | 备注 |
| --- | --- | --- |
| 图片预览 | 2 MB/张 | 移动端预览/日常查看版本 |
| 图片原图 | 20 MB/张 | 仅在业务明确选择保留原图时上传 |
| PDF | 20 MB/文件 | 私有/公开由资料策略决定 |
| 音频 | 50 MB/文件 | 不在 API 服务器转码 |
| 视频 | 500 MB/文件 | 必须是平台允许的兼容成品，不在 API 服务器转码 |

实际上传仍须由 API 在签发上传凭证前校验声明类型、大小、归属和权限，并在对象存储完成后核对服务端对象元数据。

## 6. 在线题库与考试

### 6.1 题型

- 单选题、判断题、多选题。
- 视频案例题：视频是题干素材；每道题仍是单一作答类型，由出题者自行选择客观或主观形式。视频客观题可进入自动判分和错题本；视频主观题按人工阅卷处理。
- 主观简答题支持文本和图片答案；图片是同一道人工评分题的证据，不单独产生分项分数。

### 6.2 练习

- 顺序/随机练习均可使用。
- 提交后即时显示对错、正确答案和解析。
- 练习支持随机抽题和打乱选项。
- 练习可无限重做。
- 错题本自动收录：练习错题、正式考试客观错题、视频/多选客观错题。主观题不自动按“错题”处理。
- 同一题连续答对两次后从错题本移除，但保留历史作答记录；中途答错则连续次数归零。

### 6.3 考试发布与快照

- 编辑可直接发布考试，但必须通过完整性校验：题目集合、答案、解析、题内分值、题型权重、媒体对象、时间窗口、考试公式和报名条件均完整可解释。
- 支持草稿和发布状态。
- 发布时冻结考试题目快照、顺序、答案、解析、分值和规则配置。
- 固定题目顺序；不同考生只打乱选择题/判断/多选的选项顺序。
- 题目或资料后续修改生成新版本；历史考试、答卷和审计始终引用原版本。
- 考试支持开放/截止时间、时区、报名条件、限时、尝试次数、冷却期、成绩取值和反馈/解析策略配置。
- 正式考试可按考试策略限制公开范围、组织、邀请码和报名资格；资格可检查组织成员/邀请码，平台认证和组织认证条件按考试配置决定。MVP 不把学习进度作为强制前置条件。

### 6.4 考试作答与断线

- 正式考试必须在线进行；断线可以恢复服务端状态，但计时不暂停。
- 同一用户在同一考试只允许一个活动会话；换设备重新进入时旧活动会话失效。
- 选项、文本和图片变化逐题保存到服务端；服务端时间和最后确认版本为权威。
- 主观图片先由前端压缩，再由浏览器直传私有对象存储；限制格式、数量、尺寸和总大小。
- 用户提交后该次尝试立即消耗一次机会，进入最终状态计算或待阅卷。
- 截止时允许固定几秒的宽限同步窗口，仅接收在规则允许范围内到达的最后确认请求；窗口结束后只使用服务端最后确认版本。
- 未作答题按 0 分，客户端未同步输入不计入；前端必须明确提示。

### 6.5 判分与成绩

- 客观题默认完全匹配：单选/判断选对得分，多选必须与标准答案完全一致，错题/空题 0 分。
- 题目配置基础分；考试配置题型权重。先按题内分值计算各题型得分，再按题型权重归一化到总分；权重总和和舍入规则由发布校验保证。
- 主观题配置满分、评分说明和可选参考答案；阅卷员在 0 到满分之间评分并写评语，文本和图片合并为一道题评分。
- 主观题是否计入总分、题型权重、及格线、舍入、重考成绩取值由考试配置决定。
- 每次尝试状态：`in_progress`、`pending_review`、`passed`、`failed`。
- 含主观题的尝试提交后先进入 `pending_review`；平台阅卷员提交即生效，管理员抽查改判时保留原分、改判分、理由和操作者。
- 考试汇总按发布时配置的“最高分 / 最后一次 / 首次通过”等规则计算；只有最终状态的尝试参与汇总，待阅卷尝试暂不参与。汇总随阅卷完成重新计算。
- 通过考试只产生不可变成绩、答卷和通过记录，不自动改变认证级别或认证状态。
- 题目解析和考试结果展示按考试策略配置，可立即展示、延迟展示、只展示摘要或只展示总分。

### 6.6 考试媒体与留存

- 主观题图片答案使用私有对象存储，阅卷员、考生和授权管理员按范围获取短时访问链接。
- 图片答案随答卷长期保留，作为阅卷和申诉证据；不把签名 URL 保存到数据库、日志或默认缓存。

## 7. 认证与资质

### 7.1 两类认证

- **组织认证**：由组织认证员审核，仅在签发组织内有效。
- **平台认证**：由平台管理员独立审核，跨组织有效。
- 两条申请路径独立；两类认证可并存，撤销和申诉互不自动影响。
- 同一裁判在同一组织只保留一条当前有效组织认证记录；历史审核版本和审计保留。
- 组织认证员可审核国家级、一级、二级、三级任意级别；级别不排序，只用于展示、筛选和审核记录。

### 7.2 组织认证

1. 裁判提交级别、证书编号/发证机构/取得信息、原件图片或 PDF、个人声明/补充说明和执裁履历证明。
2. 组织认证员必须核对结构化字段、私有原件和执裁履历，并填写审核备注。
3. 通过后立即生效，可用于本组织选派资格提示。
4. 认证员不能审核本人申请；组织所有者可兼任认证员，但同样不得自审。
5. 认证员角色被撤销后，历史已审核认证保留，权限立即失效；新申请不能再由其处理。

### 7.3 平台认证

- 平台认证申请人必须拥有当前有效的组织认证、仍是该组织正式成员，且组织处于平台审核通过状态。
- 任意组织的有效组织认证可以作为申请入口；组织认证只是推荐材料，不自动通过。
- 平台管理员独立核验材料并决定平台认证的通过、驳回或补件。
- 证书原件按审核范围短时可见：组织审核员只能查看本组织范围，平台审核员只能查看平台申请范围；不能通过后台任意浏览其他组织材料。
- 认证原件长期保存在私有对象存储；申请人和对应审核范围人员可通过短时授权查看。

### 7.4 认证状态与申诉

最小状态包括：`draft`、`submitted`、`under_review`、`approved`、`rejected`、`suspended`、`revoked`、`appeal_pending`、`needs_more_information`。成员退出/被移除时，组织认证进入 `suspended`；重新加入同一组织后，未被撤销的记录可恢复。

- 驳回和撤销均可申诉，申诉期间原认证状态不变。
- 申诉由更高权限管理员或指定复核员处理；原审核员不得处理自己的申诉。
- 结论可为维持、改判或要求补件；所有材料版本、操作人、时间、理由和范围进入审计。
- 认证撤销不改写历史成绩和历史选派；阻止未来新选派或接受。已发布但尚未接受的邀请保留记录，但禁止接受并提示替换。

## 8. 赛事、选派与赛后记录 Beta

### 8.1 资源层级与岗位

```text
组织 -> 赛事 -> 比赛 -> 岗位
```

- 使用预置岗位模板，可配置岗位人数和认证范围要求；首发不允许完全自由定义岗位规则。
- 岗位只配置平台认证/组织认证范围和人数；级别仅展示/筛选/留痕。
- 候选裁判必须是所属组织正式成员。
- 组织者人工选择候选人；系统展示认证来源、级别、可用性和履历提示，不自动排序或强制阻断。
- 如果组织者选择不满足岗位认证范围的候选人，必须填写理由并二次确认；记录操作者、时间、岗位和当时资质快照。

### 8.2 比赛和岗位状态

比赛最小状态：`draft`、`published`、`partially_confirmed`、`confirmed`、`in_progress`、`completed`、`cancelled`、`exception`。

岗位最小状态：`pending_acceptance`、`accepted`、`declined`、`expired`、`replacing`、`replaced`、`completed`、`cancelled`。

- 草稿可编辑；发布后名单锁定，不允许普通增删岗位或修改人数。
- 发布后每个岗位独立等待接受；所有必需岗位接受后比赛可进入 `confirmed`。
- 接受/拒绝/超时均记录原因（若有）、时间和操作者。
- 组织者或裁判长发起替换，替代者接受后岗位进入 `replaced`；原裁判和替代链路保留。
- 组织者可取消整场比赛。
- 未开始比赛可变更时间/地点；已接受岗位收到站内/邮件通知，时间或地点发生变更后岗位回到待确认并必须重新接受。
- 不允许普通岗位编辑绕过替换流程。

### 8.3 通知与联络

- 首发使用站内通知和邮件；短信作为后续增强，不阻塞 MVP。
- 支持邀请、接受、拒绝、替换、时间/地点变更和赛前提醒。
- 赛前联络采用结构化确认：比赛时间、地点、集合时间、联系人、岗位和确认状态；不做即时聊天。

### 8.4 签到与赛后记录

- 每场比赛生成专属动态签到码/二维码，在配置时间窗内有效；所有已选派裁判都必须签到。
- 每个岗位的签到记录包含时间、状态和必要的设备/操作元数据；组织可人工纠正，必须填写原因并审计。
- 主裁完成签到后可以提交一份比赛主记录；其他裁判签到状态作为记录字段和审核提示。
- 主裁无法提交、缺席或逾期时，裁判长可以接管并记录原因。
- 赛后记录支持图片元数据和到场签到信息；不在 MVP 强制建设复杂结构化比赛统计。
- 赛后图片前端生成压缩预览；原始相机文件由用户选择是否一并上传。预览用于日常查看，原图用于争议复核。
- 图片限制沿用媒体策略默认值：预览 2 MB/张、原图 20 MB/张；两类对象均走浏览器直传私有对象存储，API 只处理上传意图和元数据。
- 主记录有比赛结束后的提交截止时间；逾期标记并通知，裁判长可延期、代提交或标记缺失，全部留审计。
- 组织者审核主记录：`submitted` → `approved` 或 `returned`。退回必须填写原因；允许在期限内补交。通过后形成只读归档版本。
- 原图和预览随记录长期保留；授权人员通过短时链接查看/删除，删除必须审计。

## 9. 离线裁判工具 Beta

### 9.1 比赛工作台

计时器、犯规、24/8 秒事件和操作日志统一属于一个本地比赛工作台，会话可恢复、导出和清理，不自动同步到业务比赛记录。

- 多计时器实例。
- 开始、暂停、恢复、重置操作日志。
- 声音/震动提醒；浏览器不支持时优雅降级。
- 页面切换或锁屏后按时间戳恢复，不依赖持续运行的 JavaScript 定时器。
- 24/8 秒采用手动事件 + 默认规则集参数推算，只做提示，不作最终裁决。
- 记录台以队伍为最小颗粒度，不维护队员名单或个人犯规；支持队伍比分、技术统计、球队犯规及暂停，提示不替裁判作最终决定。详细行为见[队伍级记录台规格](0003-team-scorer-console.md)。
- 新建会话绑定当前规则版本；历史会话按创建时版本恢复并展示版本号。
- 会话只存在设备本地，用户可导出、删除单个会话或清空全部；页面提示共享设备风险。

### 9.2 GB 2312 区位码

独立于篮球罚则工具，支持：

- 汉字 ↔ 区位码双向查询。
- 区位码、国标码、十六进制机内码等表示。
- 英文、数字和符号查询，并明确与汉字区位码的区别。
- 批量文本转换。

### 9.3 规则版本

MVP 提供一套默认规则集；管理员可调整关键参数并生成新版本，不开放任意规则编程。新会话使用新版本，历史会话继续使用创建时版本。

## 10. 论坛 Beta

### 10.1 内容与互动

- 登录用户可浏览、发帖和回复。
- 板块由管理员维护，首发可覆盖判例探讨、装备测评、执裁心得等预置板块；用户不能自建公共板块。
- 支持标签、点赞和收藏；不做私信/关注。
- 发帖/回复展示昵称、头像和认证徽章，不展示证件或默认实名。
- 内容支持白名单富文本和附件；服务端再次清洗富文本，禁止脚本、嵌入代码和危险链接。
- 附件首发允许图片、PDF/文档、音视频和外部链接。仅做同步基础校验：格式白名单、大小、对象存在性和上传完整性；校验失败阻止发布。平台不承诺病毒扫描。
- 附件发帖后立即可见，但仍受同步基础校验、举报和下架机制约束；下载/外链展示安全警示。

### 10.2 审核与处罚

- 采用发后审核 + 举报 + 关键词/频控。
- 版主/审核员可隐藏、恢复或永久隐藏帖子/回复；作者限时编辑，删除为软删除，后台保留审计和取证。
- 支持按时长禁言/封禁、解除和到期。
- 支持用户申诉，记录处罚原因、证据和处理结果。
- 违规内容和附件不因“立即可见”而免除下架、审计和账号处罚。

## 11. 媒体和对象存储统一规则

所有资料媒体、认证原件、考试主观图片、论坛附件和赛后记录图片均遵循 ADR 0002：

1. 客户端请求上传意图；API 校验身份、作用域、类型、大小和归属。
2. API 创建待上传元数据并返回短时、精确范围的上传授权。
3. 浏览器直传对象存储；API 不代理、不缓冲、不转码媒体。
4. 通过对象存储通知或服务端核验的完成请求确认对象存在、大小、类型和归属。
5. 只有核验成功的对象才进入可用/已发布/可阅卷/已归档等业务状态。
6. 访问通过当前权限检查后签发短时读 URL；不保存签名 URL，不放入默认 PWA 缓存或日志。
7. 失败、过期和孤儿对象由有界清理与对象存储生命周期策略处理。

## 12. 高风险审计与数据留存

### 12.1 必须审计

- 认证和权限：组织审核、角色授予/撤销、认证通过/驳回/撤销/申诉、范围变化。
- 考试和题目：考试发布/冻结、题目版本、判分公式、成绩改判、阅卷复核。
- 媒体和隐私：查看/下载证书原件、考试图片、赛后原图；删除媒体；签发短时访问授权。
- 论坛治理：隐藏/恢复、禁言/封禁、申诉、关键词规则和版主操作。
- 选派和履职：资格越过理由、岗位状态变化、签到纠正、替换、赛后记录退回/归档。

### 12.2 审计可见性

- 平台管理员查看平台级审计。
- 组织负责人查看本组织范围的业务审计。
- 普通用户查看与本人资源直接相关的操作摘要。
- 审计记录不可由业务用户修改或删除；留存期限和脱敏策略需按部署地法律/赛事要求配置。

### 12.3 注销与留存

用户注销采用分类型留存：账号和可识别个人资料按适用政策删除或匿名化；认证、考试、赛后记录和安全审计按赛事/法务留存期限保留并尽可能去标识。不能简单删除所有历史成绩和比赛档案。

## 13. 可测试验收标准

### 学习与考试正式模块

- [ ] 未验证邮箱用户不能启动正式考试、提交认证、创建/运营组织或发帖。
- [ ] 资料可按最多三级分类筛选；一份资料可出现在多个分类。
- [ ] 编辑发布资料后，登录用户可见；下线后不可被普通用户继续访问，历史版本仍可被既有考试引用。
- [ ] 上传超出媒体类型默认/后台限制时，API 不签发上传授权；API 进程不接收媒体字节。
- [ ] 练习提交后即时显示判分与解析；错题连续答对两次后移出，历史作答仍在。
- [ ] 正式考试使用不可变题目快照；不同考生题目顺序相同、选项可不同顺序。
- [ ] 同一考试只能有一个活动会话；断线恢复服务端最后确认状态，计时不暂停。
- [ ] 自动交卷只接收固定宽限窗口内的有效同步；最终只使用服务端版本，空题为 0 分。
- [ ] 含主观题考试在阅卷完成前显示待阅卷；阅卷提交后按考试公式重新计算汇总。
- [ ] 管理员改判保留原分、改判分、理由、操作者和时间。

### 认证正式模块

- [ ] 组织审核前无组织业务权限；一次性平台邀请码可按规则直接通过创建审核。
- [ ] 组织认证员只能审核本组织成员；不能审核本人；组织认证立即生效且不跨组织。
- [ ] 平台认证申请必须有当前有效组织认证和有效成员关系；平台管理员独立复核。
- [ ] 组织/平台认证撤销与申诉相互独立；历史记录不被改写。
- [ ] 证书原件始终为私有对象；只有申请人和对应审核范围人员可取得短时链接。
- [ ] 认证级别展示和筛选不执行高低排序；岗位只校验认证范围提示。

### 选派 Beta

- [ ] 未审核组织不能创建真实赛事、比赛或选派。
- [ ] 候选人必须是所属组织正式成员。
- [ ] 发布后不能普通修改岗位人数/配置；替换、取消和时间地点变更走专门流程。
- [ ] 不满足认证范围时允许继续，但必须填写理由并二次确认，保存资质快照。
- [ ] 所有已选派裁判可在动态码时间窗内签到；签到纠正需要原因和审计。
- [ ] 主裁签到后可提交主记录；裁判长可接管；组织者可通过/退回并形成只读归档。
- [ ] 逾期记录被标记并通知；裁判长可延期或代提交，相关动作可追溯。

### 工具和论坛 Beta

- [ ] 工具会话可离线恢复、导出、删除和清空，且绑定规则版本。
- [ ] 24/8 秒和犯规工具仅提示，不给出不可覆写的最终裁决。
- [ ] GB 2312 查询支持双向、派生码、英文数字符号和批量转换。
- [ ] 论坛富文本服务端清洗；危险标签/链接被拒绝或降级。
- [ ] 附件基础校验失败时禁止发布；帖子/附件可被版主隐藏、恢复和审计。
- [ ] 作者限时编辑、软删除；版主处罚和申诉均有记录。

## 14. 实现前仍需配置的参数

以下项目的业务方向已定，但具体数值/供应商参数不能从需求推断，应在实现或部署 ADR 中明确：

- 邮箱验证码有效期、发送频率、尝试次数和密码策略。
- 资料、考试、论坛附件、认证原件和赛后原图的具体格式白名单、总大小/数量上限、对象存储生命周期和下载 TTL。
- 考试限时、宽限同步秒数、报名窗口、尝试次数、冷却期和成绩取值默认值。
- 主观题图片数量/尺寸/总大小上限。
- 签到码时间窗、赛后提交期限、退回重交次数和通知重试策略。
- 规则集参数的初始值和版本命名。
- 审计与认证材料的法定/赛事留存期限、脱敏和删除审批规则。
