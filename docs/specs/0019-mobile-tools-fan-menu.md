# FS-0019：移动底栏工具扇形菜单

- 状态：已实现；自动化与 Chrome CSS viewport 验收通过，未执行项见第 5 节。
- 范围：`apps/referee-web` 移动底栏（小于 `tablet` 断点）的「工具」入口；桌面主导航、工具汇总页与各工具页面内容不变。
- 前序规格：[FS-0006](0006-home-navigation.md) 的模块路由与建设状态、[FS-0018](0018-forum-first-home.md) 的首页编排继续有效；本规格调整移动底栏「工具」的展开方式，并为此在工具目录中加入一个明确的占位工具（见 §2.1）。
- 视觉与工程依据：[共享 UI 规范](../ui/macos_fiba.md)、[样式规约](../agents/coding-standards/styles.md)、[前端规约](../agents/coding-standards/frontend.md)。
- 任务入口：[移动工具扇形菜单](../../.scratch/mobile-tools-fan/spec.md)。

## 1. 目标与非目标

移动端场边使用时，「工具」是最高频入口，但点进 `/tools` 后还要再选一次工具。本规格让「工具」直接展开扇形快捷入口，减少一次页面跳转，同时保留通往全部工具汇总页的路径。

非目标：不实现新的工具业务、不改变既有工具页面的内容与路由、不改桌面主导航、不引入新的交互依赖或全局状态、不改变底栏其他四个入口的行为。除 §2.1 的占位项外不新增工具。

## 2. 用户可见行为

1. 移动底栏「工具」由链接改为按钮，点击（或键盘 Space/Enter）在原地展开扇形菜单，不直接跳转。
2. 扇形以「工具」按钮为圆心向上展开，三个工具入口沿 ±44° 弧面均分，半径 144px，文字保持直立。
3. 三个工具入口顺序固定：本地比赛工作台 → GB 2312 区位码工具 → 规则速查；顺序不按使用频率调整。
4. 「全部工具」不占弧面位置，而是弧面下方居中的沙金胶囊（44px 高），进入 `/tools` 工具汇总页；点击任一入口后菜单收起并跳转到对应页面。
5. 点击遮罩、按 Escape、路由变化或视口达到 `tablet` 断点时收起；达到断点时底栏与扇形都不再显示。
6. 「工具」按钮在工具汇总页为当前页（`aria-current="page"`），在工具子页面为栏目位置（`aria-current="location"`），与底栏其他入口的高亮规则一致。
7. 本地比赛工作台沿用独立场边布局，不显示底栏，因此其页面上不出现扇形菜单。

### 2.1 第三个工具入口为占位

仓库当前只有工作台与 GB 2312 两个可用工具。为验证并固定「三工具 + 全部工具」的排版，`规则速查`（`/tools/rules`）作为占位工具加入 `toolEntries`：

- 可用性为 `planned` + Beta，状态文案「建设中 · Beta 规划」，页面复用建设说明组件，不提供任何查询能力。
- 本项扩展了 [FS-0006](0006-home-navigation.md) 工具目录（工作台 + GB 2312 两项）的既有范围；真实实现或下线占位工具时必须同步更新 `toolEntries`、扇形短标签与本规格，不允许让占位入口长期冒充可用工具。
- 占位工具不选用工作台的子功能（计时、犯规、比分），避免把子功能重复包装成独立模块（FS-0006 §3.2）；真实工具上线后必须替换该占位项。

## 3. 可访问性与交互约束

- 触发按钮为原生 `button`，带 `aria-expanded`、`aria-controls` 与 `aria-haspopup`；扇形容器使用带名称的 `nav`（裁判工具快捷入口），入口为真实链接。
- 「全部工具」与工具入口分属两个层级：工具是弧面上的圆形按钮，目录入口是下方胶囊，避免把目录误当成第四个工具。
- 展开后焦点进入第一项；Escape 收起并把焦点交回触发按钮。遮罩仅承接鼠标收起，且不进入可聚焦序列。
- 入口圆形按钮 56px、整项触控区域 72×79px，「全部工具」胶囊 110×44px，均不小于 44×44 CSS px；文字标签带纯白底，避免叠在正文上降低对比度。
- 遮罩使用炭黑 35% 半透明（`bg-ink/35`），保证扇形与底栏在浅色画布上仍是视觉焦点；不使用渐变、发光或厚重阴影。
- 入场只改变透明度与缩放，不引起布局位移；系统 reduced-motion 由既有全局规则压制。

## 4. 验收标准

1. 移动端点击「工具」展开三个工具入口与「全部工具」胶囊，且不改变当前 URL；点击任一项跳转到对应路由并收起。
2. 桌面断点（≥960px）不渲染底栏与扇形，桌面主导航「工具」仍直接进入 `/tools`。
3. 320、375、390、640px 宽度下扇形不产生页面级横向溢出，也不遮挡底栏其他入口；「全部工具」胶囊与两侧工具项各留 12px 间距。
4. 键盘：Space 展开、Tab 在入口间移动、Escape 收起并回到触发按钮；`aria-expanded` 与 `aria-current` 与页面状态一致。
5. `pnpm --filter @refs-tools/referee-web test`、`typecheck`、`build`、`test:styles` 通过，产物体积变化可解释。

## 5. 验证记录与限制

- 前端单测 20 个文件、110 项通过（`test/tools-fan.test.ts` 6 项覆盖入口顺序与短标签、「全部工具」独立于弧面、占位工具路由、角度对称、栏目高亮）；`typecheck`、生产构建、`test:styles` 通过。
- Chrome 390×844：点击展开、点击遮罩收起、点击「全部工具」进入 `/tools` 并收起、点击「规则速查」进入 `/tools/rules` 并收起、工具子页 `aria-current="location"`、`/tools` 为 `page` 均通过；Space 展开后焦点进入「工作台」，Escape 收起并回到「工具」按钮。
- Chrome 320×640 实测几何：工具项 x=16/116/216，宽 72px；「全部工具」胶囊 x=98、宽 110px、y=516～560，与两侧工具项底边（504）及底栏顶边（572）各留 12px；`scrollWidth` 等于可视宽度，无横向溢出。1280×900：底栏 `display: none`，扇形不残留，桌面「工具」链接指向 `/tools`。
- 占位工具页 `/tools/rules` 展示「建设中 · Beta 规划」，不提供查询操作；`/tools` 目录同步列出三项，其中占位项标为建设中。
- 遮罩初版 15% 在正文密集页面上偏弱，按评审意见改为 35%；随后按评审把入口调整为「三工具弧面 + 全部工具胶囊」，重做 390×844 与 320×640 截图确认层次与间距。
- 限制：Enter 键激活在本 harness 中未稳定触发（同 FS-0018 记录），原生 `button` 的 Enter 行为依赖浏览器默认实现，需人工复核；CDP 视口覆盖不会派发 media query `change` 与 `resize` 事件，断点自动收起逻辑未能在此环境验证，`tablet:hidden` 已作为样式兜底。本 harness 在多次视口覆盖后出现点击坐标错位，部分交互改用 DOM 点击验证（只能证明 Vue 事件绑定与路由，不等同原生输入验收）。真机、Safari/Firefox、最大系统字体与屏幕阅读器未验收。
