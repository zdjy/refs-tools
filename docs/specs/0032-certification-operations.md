# FS-0032：认证办理 SOP 与审核工作台优化

- 状态：已实现；自动化、独立 PostgreSQL 与测试数据浏览器主路径通过，真实对象存储全链路及完整可访问性验收待补。
- 类型：software，认证业务操作工作台；沿用 Courtside（裁判端）与 FS-0010（管理端）。
- 依据：FS-0030、FS-0031、ADR 0036。保留材料必填、范围隔离、状态转换、自审与申诉回避等规则。
- 用户确认：覆盖本人申请、组织审核、组织申诉复核、平台管理端审核/复核；申请分步填写并核对提交；桌面分栏、手机独立详情；显示实名、昵称和账号标识；补齐已批准/已暂停记录入口；处理后停留结果，手动进入下一条。
- 设计适配：采用 design-taste-frontend 的清晰文案、统一系统、对齐和交互反馈原则。其整屏营销分节、随机主题、远程字体、展示特效及配套营销布局检查不适用于本工作台，遵循项目已有主题与业务验收。

## 1. 裁判办理 SOP

1. 平台认证从全局「我的」或用户菜单进入；组织认证在组织工作区「本组织认证」标签内办理。两处仅展示对应范围，已有同范围记录时继续办理原记录。入口与旧链接兼容见 FS-0031 §1。
2. 确认当前入口固定的认证范围、适用范围、材料清单与前置条件，不提供跨范围切换。
3. 填写级别、证书编号、发证机构、可选取得日期、个人声明；分别上传证书原件和履历，每类 1–10 个。
4. 核对范围、信息、声明与材料数量，允许返回修改。提供“保存草稿”和“提交审核”。服务器草稿仍要求材料完整，不引入私有资料本地持久化。
5. 提交时先保存，再用返回的版本提交原记录。保存成功但提交失败时明确“草稿/材料已保存，尚未提交审核”，保留记录 ID 与输入；重试不能再创建同范围记录。网络结果未知时先重新读取确认。
6. 草稿主操作为继续申请；需补件先显示具体审核理由，编辑后核对并重新提交。
7. 详情顶部展示审核状态、当前效力、审核理由及下一步；历史后置并折叠。驳回/撤销可申诉，申诉不恢复原效力。
8. 离开未保存表单、切换组织标签或组织时提醒；正在上传或写入时禁止前进、保存、切换处理对象、标签及关闭。

## 2. 审核与后续管理 SOP

- 队列分“待审核”“认证记录”“申诉复核”，依角色呈现。认证记录按状态分页查询，不展示未提交草稿，不自动排序认证级别。
- 组织认证员仅查询本组织；平台审核员仅查询平台。负责人身份不扩大普通审核权限。
- 队列和详情显示申请人当前实名（未填显示“未填写实名”）、昵称、账号标识；只作证书比对，不增加实名必填规则，不附带联系方式。身份资料只在授权审核投影出现，不写入认证历史快照。
- 桌面左队列右详情；窄屏选中后只显示详情，返回保留队列页码与位置。提供明确加载、失败与重新读取入口。
- 普通审核：核对证书信息、原件、履历与声明 → 批准/要求补件/驳回 → 填理由 → 确认。补件理由应写具体缺项；驳回理由说明依据与可申诉路径，不设强制全勾选核对门槛。
- 已批准记录提供暂停/撤销，已暂停提供恢复/撤销，仍由服务端实时校验权限与版本。危险决定显式确认。
- 申诉：对照原决定及理由、申诉说明和补充材料 → 维持/改判批准/要求补件 → 填理由并确认。申请人和原审核人必须回避；不新增指定复核员模型。
- 成功后停留当前结果，提供手动下一条与返回队列。提交中不可切换对象；刷新失败与写入失败分别表达，只重试读取。

## 3. 平台管理端

新增“认证审核”导航，接入现有平台审核/申诉接口和新增分页记录查询。具备同样的材料预览、理由确认、回避、结果停留与后续管理能力。保留管理端 Light / Dark 主题，不跨应用引用页面组件。

## 4. 查询与隐私边界

新增组织/平台认证记录分页端点，接收状态筛选；不返回草稿。队列与记录列表增加审核用途最小身份投影。普通本人摘要维持原投影。完整申诉申请与证据使用申诉授权且回避原审核人。申诉队列使用复核范围授权返回最小身份摘要；原审核人进入完整申请与证据时仍须回避。读取敏感身份应审计，与授权在同事务内完成。所有响应 no-store，材料签名仅存内存，关闭即清除。

## 5. 验收

- 分步校验、入口范围锁定、完整草稿恢复、保存后提交部分失败与原记录重试；取消离开确认后保留输入。
- 队列/记录状态筛选、实名最小投影、跨范围拒绝、实时撤权与申诉回避。
- 快速切换不会串详情；提交中不可切换；处理后停留并可手动下一条。
- 移动/桌面布局、320px 无页面横向溢出、44px 操作目标、键盘/焦点、reduced-motion；管理端明暗主题。
- 相关快速测试、数据库测试、类型检查、构建与样式产物验证。无法执行项如实记录。

## 6. 本轮验证记录

- 全量快速测试：120 文件、709 项通过；最终认证相关复跑 6 文件、44 项通过。10ms RSS 抽样峰值约 170.5 MiB（相关用例，非全量进程树上界）。
- 独立 PostgreSQL 17：认证集成 8 项通过，覆盖审核身份投影、状态筛选、排除草稿、分页、范围隔离、并发、历史与审计。
- workspace 类型检查、独立管理端类型检查、裁判端/API/管理端生产构建与裁判端 `test:styles` 通过。未新增依赖或迁移，未修改常驻库。
- 独立 headless Chrome 测试数据检查：本人草稿继续办理与核对提交、组织审核/申诉改判、平台审核/申诉改判；1440、1024、820、768、390、320px 均无页面横向溢出；决定后停留结果，管理端浅/深主题可用。
- 减弱动态实测五场景的运行中动画为 0；键盘 Tab 抽查与返回焦点已检查。管理端新增按钮通过公开根元素的局部样式补齐焦点轮廓，为有原因注释的样式例外。
- 浏览器使用替代 API 数据，不表示真实 Cookie、真实存储与上传授权链路完成端到端验收。未完成：真实 OSS/MinIO 全链路复跑、全控件键盘遍历、屏幕阅读器、真实弱网节流、长历史翻页、320px 每种弹窗逐项检查。
- 未使用营销布局/特效检查器评价业务工作台；其整屏 section、hero 与营销素材规则不适用。采用项目主题、生产样式检查与专用响应式/交互验证。
- 产物参考：裁判申请路由约 47.43 kB（gzip 14.81），组织审核约 24.66 kB（gzip 8.34）；两者均按需加载。管理端认证入口约 11 kB、详情约 12.25 kB，复用既有组件库。未保存基准产物，不能据此声称增量体积。
