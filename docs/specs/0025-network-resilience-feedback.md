# FS-0025：弱网与加载反馈

- 状态：已实施，验证记录见 §6。
- 适用应用：`apps/referee-web`、`apps/admin-web`。无后端、DTO、授权或迁移变更。
- 依据：[ADR 0030](../decisions/0030-network-resilience-and-loading-feedback.md)（判定阈值、重试边界、加载选型）、[FS-0024](0024-operation-feedback.md)（操作结果 toast）。
- 工程要求只维护在[前端规约 §6](../agents/coding-standards/frontend.md#6-弱网与加载反馈)，本文不重复定义。裁判端视觉沿用[共享 UI 基线](../ui/macos_fiba.md)，管理端沿用 [FS-0010](0010-admin-color-theme.md)。

## 1. 目标与非目标

目标：让用户在慢网、断网、超时和恢复时始终知道发生了什么、数据是否已提交、下一步能做什么；瞬时抖动不要求用户手动重试读取。

非目标：离线写入队列与自动同步、心跳探测、写操作自动重试、Service Worker 缓存与 PWA 离线壳。上述事项需先出 ADR。

## 2. 用户可见行为

### 2.1 网络状态提示

固定在视口底部的全局提示（移动端位于底部导航上方），不占文档流。

| 状态 | 触发 | 文案要点 | 消失 |
| --- | --- | --- | --- |
| 离线 | 浏览器报告离线 | 暂不能读取或提交，输入会保留 | 恢复在线 |
| 较慢 | 最早的在途请求 ≥ 3 秒，或读请求正在自动重试 | 网络较慢，仍在尝试 | 请求结束 |
| 长时间未响应 | 最早的在途请求 ≥ 8 秒 | 可继续等待或稍后重试 | 请求结束 |
| 已恢复 | 离线转在线，或慢速请求**成功**结束 | 网络已恢复 | 约 3 秒后自动消失 |

慢速请求以失败告终时**不显示**「已恢复」，页面的错误与重试入口为准。

### 2.2 加载形态

| 场景 | 行为 |
| --- | --- |
| 首次加载页面主体 | 300 ms 内不显示任何加载态；之后显示骨架；≥ 3 秒补「网络较慢」；≥ 8 秒出现「重新加载」 |
| 按钮提交 | 沿用按钮 loading 与禁用；≥ 3 秒提示「请勿重复操作」；≥ 8 秒说明结果尚未返回，失败后先刷新确认 |
| 管理端列表刷新 | 保留旧数据和表格 loading；≥ 3 秒 / 8 秒提示同上，8 秒后可「重新加载」 |
| 路由切换 | 200 ms 后出现顶部进度条；成功结束或失败（错误色）收尾；快速切换不出现 |

加载态一旦出现至少保持 400 ms。骨架为纯色块，只做透明度呼吸动画（无渐变、无位移）。

### 2.3 请求失败与重试

| 请求 | 离线 | 传输失败 / 超时 / 502·503·504 | 其他 HTTP 错误 |
| --- | --- | --- | --- |
| GET | 不发出，提示离线 | 最多自动重试 2 次，仍失败后显示错误与手动重试 | 不重试，沿用既有错误文案 |
| POST / PATCH / DELETE | 不发出，提示「未提交」，输入保留 | **不自动重试**；提示「先刷新确认是否已生效」，输入保留 | 沿用既有错误文案 |

离线时点击重试不会产生任何网络请求。

## 3. 范围

已接入：

- 裁判端：全局网络提示、路由进度条、账号设置资料读取（骨架）、账号设置保存（慢速提示）、登录与账号页会话确认（骨架）；`auth` / `profile` / `media` 网关新增 `OFFLINE` 错误码与文案。
- 管理端：全局网络提示；用户、组织、文件列表读取说明；用户保存、组织录入、文件下载 / 删除的提交说明；用户、组织、成员、文件、负责人查询的 `OFFLINE` 文案。管理端原有路由进度条（`window.$loading`）保持不变。

未接入（保持原样，后续按需补充）：裁判端邮箱更换与密码设置步骤的提交慢速说明、媒体上传进度、本地工作台（无网络请求）、管理端成员面板与负责人选择的列表读取说明。这些入口已获得传输层的离线拦截、GET 重试与全局提示，只缺局部慢速文案。

## 4. 边界情况

- **写操作超时**：服务端可能已处理。文案要求先刷新确认，不引导直接重试。
- **离线时已在途的请求**：由浏览器自行失败，按 `network` 处理，不额外拦截。
- **重试等待期间离线**：立即停止重试，抛出最后一次错误。
- **重试总预算**：30 秒，超出后不再发起新的重试。
- **多个请求同时在途**：以最早的一个计时，横幅取最差档位。
- **强制门户 / 弱信号下 `onLine` 为 true**：靠耗时升级为较慢 / 长时间未响应，不依赖联网事件。
- **屏幕阅读器**：提示区域常驻 DOM 且为 `role="status" aria-live="polite"`；骨架对读屏仅暴露一次加载说明。
- **减弱动态**：进度条与提示沿用全局 reduced-motion 基线；骨架的呼吸动画在 reduced-motion 下静止。

## 5. 验收标准

1. 离线时任意平台请求（含 GET 与写操作）不调用 `fetch`，页面显示离线错误与「未提交」说明。
2. GET 遇 503、断网后自动重试并成功，用户无需操作；遇 400 / 401 / 404 / 409 / 429 / 500 不重试。
3. 写操作失败后 `fetch` 只被调用一次。
4. 请求短于 300 ms 时不出现骨架或慢速文案；出现后至少保持 400 ms。
5. 请求挂起时依次出现：骨架 → 「网络较慢」→「重新加载」，并可重新发起。
6. 慢速请求成功后出现「网络已恢复」并在约 3 秒后消失；失败告终时不出现。
7. 320 px 视口下提示不遮挡底部导航，页面无横向溢出。
8. 传输层与网关不调用通知 API，不记录 URL、请求体或响应。

## 6. 验证记录

- 单测（Vitest）：重试退避与抖动、监视器计数与订阅、联网事件绑定与解绑、网络状态分级与恢复判定、加载时序（快速无闪烁、最短可见、升级、重复 start、dispose）、请求守卫（离线、GET 重试、写不重试、预算耗尽、等待期离线、HTTP 状态矩阵）、客户端端到端弱网行为，两端各一套；既有请求层与网关测试同步更新并通过。
- `typecheck`、两端生产构建、裁判端 `test:styles` 通过；管理端 Tailwind 3 已确认生成 `z-[6000]`、`empty:hidden` 等新增类。
- 浏览器（Chrome，注入 `fetch` 替身模拟网络，**非真实弱网**）：
  - 请求挂起：骨架在约 0.5 秒出现，3 秒后出现说明，8 秒后出现「重新加载」，全局提示依次为较慢、长时间未响应。
  - 延迟 4.5 秒后成功：骨架消失，出现「网络已恢复」并约 3 秒后消失。
  - 断网：GET 在约 0.3 s、0.6 s 后重试共 3 次，最终显示持久错误与「重新读取」。
  - 离线事件：横幅出现，点击重试未发出请求，错误文案为离线说明；恢复在线后出现「网络已恢复」。
  - 320 px：提示位于底部导航上方（间隔 3 px），无横向溢出。
  - 管理端登录页：离线提示出现且位于最上层（z-index 6000）。
  - 路由进度条：在导航中追加 1.5 秒的慢守卫模拟 chunk 下载，进度条在约 200 ms 后出现，导航完成后进入收尾；移除守卫后的快速导航中未出现。
- 未执行：Chrome DevTools 真实节流（Slow 3G）、真机弱网、屏幕阅读器播报、系统 reduced-motion、管理端各业务页的真实慢网写操作矩阵（未登录后台账号）、路由进度条的截图级视觉确认（仅验证了出现与收尾时机）、管理端路由进度条沿用原有实现，未重新验证。
