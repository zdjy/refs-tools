# FS-0031：裁判端认证工作台与组织认证审核界面

- 状态：裁判端与组织审核界面已实现；本地 MinIO 直传/读取、桌面与 390px 移动视口主路径已联调，生产存储与完整浏览器验收待完成。
- 范围：全局 `/certifications` 平台认证工作台，组织工作区内的本人组织认证面板，以及 `/organizations/:organizationId/certifications/review` 审核台。
- 依据：[FS-0030 §1–2](0030-certification-api.md)、[FS-0001 §7](0001-mvp-scope-and-business-rules.md#7-认证与资质)、[ADR 0036](../decisions/0036-certification-history-and-evidence-access.md)、[场边 UI 基线](../ui/courtside.md)。
- 后续优化：[FS-0032](0032-certification-operations.md) 接续分步申请、审核身份投影、记录管理与平台管理端审核；下述原始布局与步骤以 FS-0032 为准。
- 不在范围：指定复核员分配、通知与证据删除审批。

## 1. 本人认证工作台

`/certifications` 需要登录并验证邮箱。匿名用户只看到登录入口，不发出私有请求。

- 平台认证入口位于移动端「我的」页面（账号资料/安全设置之前）及桌面用户菜单（「我的主页」之后）；页面只显示平台认证，导航归属「我的」。沿用 `/certifications` 地址。每个组织范围与平台范围各一条记录。
- 列表只使用 `GET /me/certifications` 的摘要；逐页完整读取后按平台或当前组织范围筛选，不展示其他范围的记录。前置条件和已有记录判断使用完整摘要，不因当前分页漏判；每范围最多一条记录，不再提供本人列表翻页。选中后才读取详情、历史与申诉，并分别处理失败与重试。`effectiveStatus` 与 `status` 不同时同时显示。
- 组织工作区为所有正式成员提供独立的「本组织认证」标签，在标签内直接完成当前组织的申请、补件、进度、历史和申诉；不显示平台认证入口或引导。普通成员不需要审核权限。旧 `/certifications?organizationId=…` 深链跳转到 `/organizations/:id?tab=my-certifications`。
- 平台表单锁定 platform 范围，组织表单锁定当前组织，不提供跨范围选择。新建组织认证要求组织与正式成员关系均 active；无有效组织认证时平台申请按钮禁用并说明原因。已有同范围记录时隐藏新建按钮并继续办理原记录；前置条件失效不隐藏既有平台记录。
- 新建先保存草稿，不自动提交。草稿详情提供「提交审核」二次确认；提交后进入 `under_review`，审核期间不提供编辑入口。
- 草稿与 `needs_more_information` 可编辑材料；保存生成新版本并保留旧材料。驳回或撤销只提供申诉，不提供另建同范围记录。
- 表单必填证书编号、发证机构、个人声明、1–10 个证书原件与 1–10 个履历材料；取得日期可空且必须是真实存在的日期。字段错误就近显示，失败保留全部输入。
- 材料上传使用 `certification_evidence` 用途：组织认证目标为当前组织，平台认证为目标为空（本人）。认证范围由入口固定；不同范围仍须分别上传，不得跨范围复用。
- 查看材料只调用认证专用读取入口，弹窗内显示图片或 PDF（认证入口使用 `inline` 签名，通用入口仍强制下载）；签名 URL 只存内存，关闭即丢弃，不写日志、错误、缓存或页面文本。
- 「办理历史」折叠区显示动作、当时状态、版本、时间与操作人尾号；历史是写入当时的快照，不代表当前效力。
- 驳回或撤销且没有待复核申诉时提供「提交申诉」：理由必填并通过与服务端一致的敏感内容检查，补充材料可选，最多 10 个。待复核期间不再显示新的申诉入口。
- 写操作逐次 toast 成功结果；失败保留页面错误与输入。写入成功但刷新失败只提示「显示可能陈旧，请只重新读取」，不改报保存失败。离线请求不发出，文案说明未提交与输入已保留。

## 2. 组织认证审核

组织工作区在本人是 `certifier` 时增加「认证审核」标签，在本人是 owner 时增加「申诉复核」标签；两者同时存在时共用一个入口。标签只按角色呈现，不承担授权。

审核台 `/organizations/:organizationId/certifications/review`：

- `certifier` 可看待审核队列（`GET /organizations/:orgId/certifications/review-queue`），不请求申诉队列；owner 可看待复核队列（`.../appeal-queue`）。无相应角色时不发对应请求，也不显示对应队列。
- 队列只显示摘要、级别、状态、更新时间和申请人账号尾号；完整材料、历史与申诉在选中后单独读取，读取或决定都仍由 API 独立授权。
- 待审记录按状态可批准、驳回或要求补件；已批准可人工暂停或撤销；已暂停可恢复或撤销。决定必须填写理由，理由会记入审计并生成新版本；撤销使用危险样式。
- 申诉复核只显示待处理申诉的理由与补充材料；可维持原决定、改判批准或要求补件。原审核人或申请人本人打开时禁用决定按钮并说明必须回避；服务端仍会独立拒绝。
- 决定成功后关闭理由弹窗、逐次 toast，并刷新两个队列与当前详情。刷新失败只提示陈旧，不诱导重复提交。
- 未加入组织、没有相应角色、会话失效、离线与网络失败都有独立可见说明和恢复入口；不得伪装成空队列。

## 3. 响应式与可访问性

- 移动优先单列布局，桌面内容列最大 1080px；不把内容区块装进白色圆角卡片，分组依靠 1px 细线与标题层级（[场边 UI 基线](../ui/courtside.md)）。
- 列表行、按钮、标签页与上传控件触控目标不小于 44×44 CSS px；键盘焦点使用 2px `accent` 轮廓；状态同时提供文字与色点，错误 `role="alert"`，持久结果 `role="status"`。
- 骨架用于首次加载，已有数据刷新保留旧内容；提交按钮显示 loading 与「请勿重复操作」的慢速提示；reduced-motion 下动画静止。
- 材料、声明与审核说明属于访问受控数据，不进入 Pinia 持久化、localStorage 或 Service Worker 缓存。

- 状态层：草稿创建与选中、补件版本、提交、申诉、写入成功但刷新失败、审核决定与申诉复核、角色可见性与无权限时不请求队列。

- 组织工作区标签：普通正式成员显示「概览 / 本组织认证」，认证员增加「认证审核」，负责人显示「申诉复核」；仅有 certifier 角色、无成员管理权限时仍可进入审核。
