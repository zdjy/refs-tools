# FS-0029：组织成员联系方式查看

- 状态：已实施；验证记录与未覆盖项见 §5。
- 适用应用：`apps/referee-web`；后端 `apps/api`，共享契约 `packages/contracts`。
- 业务依据：[FS-0016 组织成员与定向邀请](0016-organization-membership.md)、[FS-0023 账号设置](0023-account-profile-settings.md)、[FS-0027 裁判端组织](0027-referee-organizations.md)。
- 决策依据：[ADR 0035](../decisions/0035-member-contact-projection.md)、[ADR 0028](../decisions/0028-organization-members-and-invitations.md)。
- 工程约束：遵循[统一编码规约](../agents/coding-standards.md)，不在此重复依赖、分层、样式或文件长度规则。

## 1. 范围

组织工作区的成员名单需要让成员管理者查看某位成员的联络资料。此前成员列表只返回昵称、状态与时间，管理者无法在不离开页面、不接触平台后台的情况下核验或联系成员。

本次交付：

1. 新增按用途最小化的成员联系方式读取接口，只服务当前组织的成员管理场景。
2. 用户端成员名单以成员姓名或整行作为入口，打开只读详情弹窗。
3. 手机号默认遮蔽，管理者主动点击后才展开整串。
4. 读取行为写入追加式审计，联系方式本身不进入审计快照。

不包含：向普通成员开放他人联系方式、管理端新增成员资料入口、邮箱或详细地址/出生日期展示、短信验证、导出或批量下载。

## 2. 数据与授权

- 投影字段：昵称（`users.display_name`）、头像媒体 ID（`referee_profiles.avatar_media_id`）、真实姓名（`legal_name`）、手机号（`phone_e164`）、地区展示文本（`region_label`）。
- 明确排除：登录邮箱、详细地址、出生日期、密码/会话/令牌、媒体签名 URL。签名 URL 仅在浏览器内存中按需获取，不写入列表响应、审计或持久缓存。
- 读取权限：当前组织的 `organization.members.manage`，即负责人与组织者；平台管理员的 `platform.manage` 不隐含该权限。每次请求由服务端重新授权，不信任客户端传入的角色或组织归属。
- 关系范围：该组织下的成员记录均可读取，包括已退出/已移除/已驳回的历史关系；它们仍属于该组织的成员管理历史，且读取会留痕。
- 审计：每次成功读取写入 `membership.contact_viewed`，资源为 `membership`，范围为该组织；快照为空，不记录联系方式。审计失败时整笔读取失败，不返回资料。
- 档案缺项按 `null` 返回，页面显示「未填写」，不推测、不回退到邮箱或昵称。

## 3. API

所有路径以 `/api/v1` 为前缀，Cookie 会话、`no-store` 与同源校验沿用组织成员接口。

| 方法与路径 | 权限 | 行为 |
| --- | --- | --- |
| `GET /organizations/:id/memberships/:recordId/contact` | `organization.members.manage` | 返回 `{ nickname, legalName, phone, regionLabel, avatarMediaId }`；记录不存在或跨组织 `404`；无权 `404`（不泄露记录是否存在） |

契约位于 `packages/contracts/organization-members` 的 `MemberContactSchema` 与 `MemberContactResponseSchema`。

## 4. 页面与交互

- 成员名单的昵称是可聚焦按钮，点击打开详情弹窗；每行左侧整体就是该按钮（首字母 + 昵称 + 状态），点击整行也打开同一弹窗。批准/驳回/移除是它的兄弟节点，各自独立命中，不依赖事件冒泡拦截（版式见 [FS-0027](0027-referee-organizations.md) §17）。
- 弹窗只读展示头像、昵称、成员状态与加入/申请时间、真实姓名、手机号、地区；不提供编辑入口。
- 手机号默认按位遮蔽（保留前 4 位与后 4 位），提供带 `aria-pressed` 的「显示 / 隐藏」按钮；展开后为等宽可选中文本。
- 头像按需申请读授权；签名失败降级为昵称首字，不影响联系方式读取。
- 首次读取使用既有骨架与「较慢 / 未响应」提示；失败保留弹窗与就近错误，提供「重新读取」，不显示成空资料。
- 关闭弹窗清空联系方式、头像签名与错误；恢复触发元素焦点（行可能已因刷新被移除，恢复前检查 `isConnected`）。
- 弹窗内说明联系方式仅用于成员管理与联络、查看会记入审计。

## 5. 验证与未覆盖

- 后端用例覆盖：负责人读取投影、平台账号被拒绝、记录不存在、审计失败不返回数据。
- 已验证：`pnpm typecheck` 四个包通过；`pnpm test` 111 文件、647 项通过；`pnpm test:db` 16 文件、84 项通过（首次全量运行有一项与本改动无关的平台邀请码用例瞬时失败，单文件重跑与第二次全量重跑均通过）；`test:styles` 与 `vite build` 通过，组织工作区分块 206.73 kB（gzip 57.54 kB），CSS 51.00 kB（gzip 9.03 kB）。
- HTTP 覆盖：合法读取只返回契约字段且不含邮箱/详细地址；非法记录 ID 返回 `400`；匿名读取返回 `401`。同源校验沿用组织成员路由的写请求门禁。
- 真实 PostgreSQL 覆盖：实名/手机号/地区投影、历史关系可读、跨组织 `404`、`membership.contact_viewed` 审计落库、邮箱/详细地址/生日不进入响应。
- 前端覆盖：网关路径编码、媒体读授权、手机号遮蔽、详情读取与头像降级、失败重试、旧响应不覆盖新成员、关闭清空私有状态。
- **浏览器实测（Chrome 156 headless，CDP；本机开发 API + 开发库，`https://localhost:8443`）**：在「测试协会」中以负责人会话打开成员标签，真实数据含负责人、正式成员、无资料成员和待审核申请人。
  - 桌面 1280×900：表格四列与负责人标记正确；打开前没有 `/contact` 请求，点击姓名后只发一次；zdjy 的头像、实名、地区、遮蔽手机号正确，完整号码在点击「显示」前不在 DOM 中；「显示 / 隐藏」往返正常；关闭后焦点回到姓名按钮；无资料成员显示 3 个「未填写」且无头像图片，回退首字；待审核行保留「驳回 / 批准」且姓名仍可查看联系方式。
  - 网络失败：用 CDP 阻断 `/memberships/*/contact` 后打开详情，弹窗内出现可重试的连接错误且不把失败显示成「未填写」；解除阻断后点「重新读取」成功加载。拦截期间 GET 自动重试次数与手动重试均可见，符合既有弱网策略。
  - 320×800：页面无横向溢出；表格在自身 640px 滚动容器内横滑；弹窗边界为 16–304px（视口 320px），弹窗内按钮均不小于 44×44px；控制台无运行时错误。
  - 权限：以普通成员 zdjy 的会话直接请求 contact 返回 `404`，成员标签页本身也不对其显示。
  - 审计：每次成功读取均落 `membership.contact_viewed`，`before/after/reason` 为空，不含联系方式；测试数据随后清理，审计行按追加式约束保留。
  - **实测中发现并修复**：姓名按钮是原生 `<button>`，项目未启用 Preflight，默认边框与底色使其看起来像输入框；已显式清除 `border/background/padding` 并保留 44px 触控高度与焦点环。
- **未覆盖**：未测真实手机与 375/480/640/768/960/1100/1536 等中间断点；未测 Light/Dark、reduced-motion；未用真实键盘 Tab 遍历弹窗焦点陷阱（只验证了聚焦姓名按钮后的关闭焦点恢复）；未点击「批准 / 驳回 / 移除」以免改动测试数据；未验证大规模成员或弱网下的弹窗性能。

## 6. 版式修订：成员名单回归场边平铺列表

- 成员名单原先按管理端习惯改为 `NDataTable` 四列表格，与本应用「内容直接铺在暖沙画布上、用 1px 细线分段」的基线冲突：表头软底色、外框、单元格分隔线构成了一块表格壳，状态用彩色 `NTag` 胶囊，操作列在无可执行操作时还要显示占位「—」。现改回平铺列表行（[FS-0027](0027-referee-organizations.md) §17），详情弹窗、权限、接口与写入行为均未改动。
- 对本文的影响：只有「详情入口在行内的位置」一项。昵称仍是可聚焦按钮，点击昵称或整行打开同一弹窗；状态与时间以「色点 + 状态文字 · 加入/申请于 日期」呈现，不再需要表头解释列含义。
