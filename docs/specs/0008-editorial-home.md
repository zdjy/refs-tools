- 业务与导航基础：[FS-0006](0006-home-navigation.md)。
- 视觉基线：[共享 FIBA UI 规范](../ui/fiba_about_ui_specification.md)，保持原规范不变。
- 工程约束：[编码规约](../agents/coding-standards.md)。

## 1. 范围与真实性

用户确认本阶段交付“内容型首页与阅读体验”，不接入真实学习与论坛业务。首页从模块卡片集合改为编辑式内容：精选导读、学习专题、社区讨论示例、赛前核对清单与辅助模块导航。

本规格替代 FS-0006 第 3 节的固定首页顺序、标题及八张卡片形式；八个业务模块及其状态、路径保留在折叠的“全部功能”中。其余身份、导航、工作台安全、授权和离线边界不变。FS-0006 中“无模拟业务数据”继续有效：讨论内容明确标注“讨论示例”，不冒充真实论坛帖子。

- 学习内容为随应用发布的自编导读，不冒充官方规则、已发布的 LearningAsset 或个性化推荐。
- 三篇学习导读：观察位置与视角、规则版本核对、赛前协作；两篇讨论示例：接触画面复盘、赛后记录事实表达。
- 不展示虚构作者、头像、认证、发布时间、浏览量、回复数、热门排名、学习进度或赛事数据。
- 讨论示例详情展示情境、讨论问题与示例思路，持久说明不是用户发帖、不提供真实回复或发布能力。
- 内容只提供观察与准备方法，不给出规则集无关的统一罚则；适用版本与组织规程由使用者核对。
- 不新增 API、跨端 DTO、数据库、登录要求、缓存、同步、收藏或学习进度。

## 2. 视觉方向

沿用现有暖白、暖沙金、暗沙折面、纯白、炭黑与球场红 token，系统字体、圆角、胶囊按钮及微阴影不变。以非对称主专题、原创球场观察示意和大标题建立视觉焦点；其余内容保持克制，避免所有信息切成等大入口卡片。

主要参考 [FIBA 机构官网](https://about.fiba.basketball/en)：借鉴专题、资讯与长期资料并存的内容层次，不照搬机构栏目、官方身份、品牌素材或未经授权的图片。Awwwards 作为构图与细节的辅助参考，优先级低于共享 UI 规范。

辅助参考 Awwwards 体育案例：

- [Boom Ball](https://www.awwwards.com/sites/boom-ball)：借鉴以体育主题建立主视觉与内容叙事，不采用其高彩度风格。
- [Montreal Canadiens Foundation](https://www.awwwards.com/sites/montreal-canadiens-foundation)：借鉴体育与社区内容结合、主次编排；不引入其彩色体系、加载动画或视差。

可访问性窄范围适配：暖白画布上的小字号红色眉题使用现有 `redHover` token（对比度约 5.65:1），因为 `red` 在该背景约 4.36:1，不满足普通小字 4.5:1；图标、非文字强调与大字仍使用原球场红，不新增色值。

主视觉为本地原创 SVG 球场示意，明确注明“非站位标准”，不使用外部图片、远程字体、WebGL、滚动劫持或持续自动播放动效。所有产品图标统一为 Lucide，禁止 emoji。仅使用轻量、响应用户动作的平滑过渡，尊重 reduced-motion。

## 3. 信息架构与交互

首页顺序：

1. 页名与定位：裁判手记，页头提供本地工作台快捷入口并说明设备存储边界。
2. 主专题：观察位置与视角，以标题、摘要、原创球场示意与阅读按钮呈现；640px 起补充三个分节直达链接，移动端保留主阅读入口，避免目录挤占首屏。
3. 社区讨论与案头资料：960px 起为非对称双栏，移动端先讨论后资料。讨论直接展示正文情境、讨论切入点与示例回应入口；案头资料展示另外两篇导读的真实分节提纲，可直达阅读页对应锚点。不添加假作者、热度或失效操作。
4. 研读室：保留全部、规则研读、执裁协作三个筛选按钮及 `aria-pressed`、结果数量反馈；默认优先规则研读，避免主专题再次占据最大内容块。首篇展示共享正文的首节节选，余篇以摘要、要点和阅读入口呈现。多篇时在 960px 起使用主次双栏，单篇时占满宽度；不再使用三个等大图标预览卡片。
5. 赛前核对清单：独立于讨论区，使用原生 details/summary 展开沟通提纲，不保存勾选或完成状态。
6. 全部功能：原生 details/summary 展开八模块及其真实建设状态。
7. 本地工作台存储与离线边界说明。

目录与节选均由现有公开内容投影，不复制正文或引入新业务模型；所有旧阅读路径、导航归属与工作台生命周期保持不变。

阅读页为五条显式静态路由：

- `/read/observation-angle`
- `/read/ruleset-reading`
- `/read/pregame-briefing`
- `/read/contact-review`
- `/read/postgame-notes`

页面展示内容类型、标题、摘要、分节正文、阅读目录及相关文章。提供返回首页；社区示例另提供社区建设状态入口，学习导读提供学习中心入口。导航栏目分别归属学习或社区。未知 slug 仍为 404，不用任意 slug 匹配业务内容。直接访问、刷新、浏览器返回及路由焦点沿用既有导航机制。

所有阅读内容均为公开的自编静态材料；未来真实受保护资料与帖子必须另走 API 授权，不能借此将业务数据打包到静态前端。

## 4. 验收

- 首页主体可阅读，不再以八个入口卡片为主要内容；专题、讨论、资料有不同呈现方式，无需点击即可看到摘要、情境和目录。所有内容链接进入已有正文或真实分节锚点。
- 研读筛选保持 3 / 1 / 2 篇匹配内容，默认主文章不与首屏专题重复；正文节选与资料目录来自共享内容，无独立文案副本。
- 示例与自编内容身份在首页和详情均可见，无虚构热度、用户或业务状态。
- 五条阅读路由显式懒加载，有正确标题与导航归属，未知内容 404。
- 筛选可切换并有选中反馈；核对清单及全部功能支持键盘展开。
- 单 H1、合理标题层级、main/nav/跳过导航、装饰图标隐藏、焦点可见；目标至少 44×44px。
- 320、375、640、768、960、1280、1536、1920px 无页面级横向溢出，底栏不遮挡内容；不依赖 hover 才能读到内容。
- 验证 Tab/Shift+Tab、Enter/Space、路由后焦点与 reduced-motion。
- 不实例化工作台状态、不访问本地比赛存储，无新增 API、第三方图片字体请求或 Service Worker。
- 相关单测、类型检查、生产构建及样式生成检查通过，记录产物差异与未执行项。
