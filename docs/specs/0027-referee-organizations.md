# FS-0027：裁判端组织、邀请、成员关系与角色

- 状态：已实施；验证记录与未完成项见 §8。
- 适用应用：`apps/referee-web`；后端 `apps/api`，契约 `packages/contracts`（`organization-self`、`organization-access`），纯规则 `packages/domain`。
- 业务依据：[FS-0002 Task 7](0002-mvp-platform-feature.md)、[FS-0016 组织成员与定向邀请](0016-organization-membership.md)、[FS-0015 管理端组织治理](0015-admin-organization-management.md)。
- UI 依据：[共享 UI 规范](../ui/macos_fiba.md)（配色与 token 不变，版式与动效在其约束内自由组织）。
- 工程约束：遵循[统一编码规约](../agents/coding-standards.md)，不在本文重新定义。选型与取舍见 [ADR 0032](../decisions/0032-referee-organization-access.md)。

## 1. 范围

FS-0016 只交付管理端与基础 API，用户端没有任何组织入口。本次补齐用户端：

1. 「我的组织」：本人的成员关系、待审核/被驳回的创建申请、收到的邀请。
2. 加入：组织目录检索 + 申请加入；成员码兑换。两个动作在用户端只有一个入口「加入新组织」，共用 `/organizations/discover` 页面。
3. 创建：自助提交组织创建申请，平台审核通过后成为负责人（审核仍在管理端）。
4. 组织工作区：概览、成员与入会审核、邀请（含按昵称/邮箱检索）、成员码、组织角色；退出组织与撤回申请。

不含：组织解散、赛事/选派/认证联动、邮件通知投递。所有权移交和平台创建邀请码（FS-0002 的 `platformInviteToken`）已由 [FS-0028](0028-platform-invites-and-ownership-transfer.md) 接续。

## 2. 路由

| 路径 | 说明 |
| --- | --- |
| `/organizations` | 我的组织（取代原建设说明页） |
| `/organizations/discover` | 「加入新组织」：成员码兑换 + 组织目录；`#code` 锚点仍指向兑换区，供深链接使用 |
| `/organizations/new` | 申请创建组织 |
| `/organizations/:organizationId` | 组织工作区；静态路径声明在动态 id 之前，id 只传给视图，授权由 API 裁决 |

全部为显式静态路由，匿名访问时页面显示登录入口且不发任何私有请求。

## 3. 行为规则

- **能力来自服务端**：`GET /me/organizations` 为每个组织返回 `canManage` 与 `canGrantRoles`，由同一份授权矩阵实时计算；界面只据此决定标签页与按钮，写请求仍独立授权。
- **状态说明**：待审核、已冻结、已驳回在名册与工作区页头用文字说明后果；被驳回时向负责人显示平台说明并提供「重新申请」。
- **自助申请**：负责人即申请人，审核通过前不建立成员关系，不授予任何角色；同一申请人同时待审核最多 3 个，超出返回 `APPLICATION_LIMIT`（409）。并发申请以事务级咨询锁串行化。
- **申请资料来源**：请求体只含 `name`、`region`、`purpose`，多出 `ownerLegalName` / `contact` 一律 400。负责人实名与联系方式不手填，服务端在同一事务内读取申请人账号资料的真实姓名与手机号（FS-0023），提交时快照写入组织记录的 `owner_legal_name`、`contact`；之后本人改资料不改写已提交申请，审核看到的是提交当时的值。资料缺真实姓名或手机号返回 `PROFILE_INCOMPLETE`（422），不写入、不占用待审核名额。联系方式取手机号（E.164），不回退到登录邮箱。
- **所在地区**：申请表单与账号设置共用同一个省/市/区三级选择器（`components/ui/UiRegionSelect.vue`），必须选到区/县；提交的是「省/市/区」展示文本，组织表只存该文本，不存行政区代码，目录与管理端关键词检索沿用文本匹配。
- **申请页的负责人区块**：页面读取本人账号资料，只读展示真实姓名与手机号并说明用途；缺项时用文字列出缺哪项，提供在新标签页打开账号设置的入口（当前表单输入不丢失）和「重新读取」，资料读到且齐全之前提交按钮禁用。读取失败显示可重试说明，不当作资料齐全。服务端返回 `PROFILE_INCOMPLETE` 时保留输入并重新读取资料。
- **目录**：仅 `active` 组织，只含名称、地区、简介、活跃成员数及本人关系；不含负责人、联系方式、名单。
- **申请加入 / 撤回**：沿用 `membership-requests`；申请人可撤回自己的 pending 申请，记为 `left` 保留历史，之后可重新申请。
- **成员码**：创建时一次性返回明文（`rj_` + 43 位 base64url），库内只存 SHA-256 与末 4 位；有效 1–30 天、可用 1–100 次，每组织同时有效最多 10 个。兑换在组织行锁内以单条条件 `UPDATE` 消费；已是正式成员幂等返回且不消耗次数；未知、撤销、过期、用尽统一返回 `JOIN_CODE_INVALID`（422）。成员码只授予成员关系，永不授予角色，重新入会不恢复旧角色。
- **角色**：仅组织负责人可授予/撤销 `organizer`、`certifier`；`owner` 不可经此接口授予或撤销；目标必须是有效正式成员。平台管理员不具备此能力。撤销绑定必须属于路径中的组织，否则 404。
- **组织简介**：概览里的组织简介只有组织负责人可编辑（按钮仅对 `isOwner` 出现）；写权限只认组织记录上的 `owner_user_id`，待审核组织尚无成员关系与 `owner` 角色也能改，平台管理员不能经此接口代替修改。请求体只接受 `purpose`（1–1000 字）与 `expectedVersion`，其他字段 400；版本条件更新与审计同事务，审计快照只含状态、版本与负责人标识，不含简介正文。状态可编辑范围复用平台同一个领域函数 `canUpdateOrganizationProfile`（待审核/运行中/冻结可改，已驳回/已解散 409）。
- **成员名单可见性**：本组织所有正式成员（含无角色普通成员、认证员、组织者、负责人）均可进入「成员」标签；待审核或已结束成员关系不授予此读取权限。普通成员仅可读取正式名单，不开放申请/历史、联系方式或管理操作；详见 §18。
- **成员名单检索**：成员标签页的关键词只按昵称子串过滤，与分页一起由服务端处理，计数与页数都是筛选后的结果，不只筛当前页；关键词在提交时生效并回到第 1 页，留空即取消筛选。界面按是否筛选区分「共 N 位成员」与「匹配 N 位成员」及两种空态；移除或审核后若当前页越界则回退到新的最后一页。
- **候选人检索**：需要组织成员管理权限；关键词至少 2 字符；含 `@` 只精确匹配完整邮箱，否则按昵称子串或实名子串匹配；实名只参与匹配，响应仍只返回有效且邮箱已验证账号的昵称、ID 尾号与关系，不返回邮箱或实名；每次检索写审计但不记录关键词。分页只接受 `page`，每页固定 10 条（`pageSize` 不由客户端指定），避免分页放大账号枚举面。管理层定向邀请与裁判端邀请使用同一接口按人选择，不再手填用户 UUID。
- **理由与二次确认**：移除、驳回、批准、撤销邀请、退出/撤回都经理由对话框，理由 ≤ 500 字符且不含链接或凭据（与服务端审计白名单一致）。成员码撤销只需版本号。
- **无需理由的二次确认**：成员码撤销、角色撤销、拒绝邀请不要求理由（服务端也不需要），但都必须先经 `NPopconfirm` 二次确认（按钮为「取消 / 确认撤销」「取消 / 确认拒绝」），并写清后果；取消不发出任何请求。

## 4. API（前缀 `/api/v1`，同源 Cookie、`no-store`）

| 方法与路径 | 说明 |
| --- | --- |
| `GET /me/organizations` | 本人组织，含角色与能力，分页（默认 `pageSize=100`） |
| `GET /organization-directory` | 公开目录，分页 |
| `POST /me/organization-applications` | 自助创建申请，201 |
| `PATCH /organizations/:id/profile` | 负责人自助修改简介，`{purpose,expectedVersion}`，回执 `{id,purpose,version}` |
| `POST /organization-join-codes/redeem` | `{token}`，兑换成员码 |
| `GET/POST /organizations/:id/join-codes` | 列表（无明文，分页，默认 `pageSize=50`）/ 创建（一次性明文） |
| `POST /organizations/:id/join-codes/:codeId/revoke` | `{expectedVersion}` |
| `GET/POST /organizations/:id/roles` | 列表（分页，默认 `pageSize=100`）+ `canGrant` / 授予 |
| `POST /organizations/:id/roles/:bindingId/revoke` | 撤销 |
| `GET /organizations/:id/member-candidates?keyword=&page=` | 候选人检索，每页固定 10 条 |

沿用 FS-0016 的成员、邀请、本人收件箱、接受/拒绝、申请与退出接口；成员名单额外接受可选 `keyword`（昵称子串，≤100 字符），邀请、收件箱等其他列表不接受。`GET /me/organizations` 的每项新增 `version`，与组织行版本一致，供简介更新的条件写入。迁移 `0009` 新增 `organization_join_codes` 与两个索引。

## 5. 交互与可访问性

- 加载：首次读取用静态骨架，已有数据的刷新保留旧内容；提交用按钮 loading + `UiSubmitHint`；写操作不自动重试。
- 失败：弹窗内就近显示错误并保留输入；写入成功但随后刷新失败时保留成功事实，只提示「重新读取」，不引导重复提交。
- 离线：请求不发出，文案含「未提交」「输入已保留」；网络失败写操作提示先刷新确认。
- 成员码明文仅存内存，关闭、切换组织、离开页面即清除；明文默认遮蔽，点眼睛按钮（`aria-pressed`）才展开整串。复制被拒时说明手动复制。
- 所有交互目标 ≥ 44px，标签页支持方向键/Home/End，错误用 `role="alert"`，状态用文字加色点，动效遵循 `prefers-reduced-motion`。错误文字使用 `text-red-hover`（在沙色/画布底上对比度 ≥ 4.5:1）。
- 确认气泡的按钮统一用 `components/ui/confirm-buttons.ts` 投影（`large` + `min-height: 44px`），避免默认尺寸低于触控目标；该文件只适配尺寸，不含文案或业务语义。
- **工作区标签栏**：手机端各标签按 `flex-1` 均分整行、以 `min-w-max` 保证文字不被截断，五个标签在 320px 起即整行放下，不出现横向滚动条；只有标签数量增加导致确实放不下时才退回局部横滑，此时同样隐藏滚动条本身（保留触摸与滚轮滚动）。选中项变化（点击、方向键、切换组织）后自动滚入可视区，`block: 'nearest'` 不改变页面纵向位置。

## 6. 数据与迁移

`0009_organization_join_codes.sql`：`organization_join_codes`（哈希唯一索引、`uses <= max_uses` CHECK、`expires_at > created_at`）、`organizations(owner_user_id,status)` 与活跃成员部分索引。down 删除表与索引。生产部署前须执行迁移，并按 [授权与审计说明](../../apps/api/db/AUTHORIZATION_AUDIT.md) 的运行账号配置授予新表权限。

## 7. 未交付与已知限制

- 没有邮件/站内通知：邀请、审核结果都需用户回到「我的组织」查看，界面文案已如实说明。
- 组织解散仍未实现；所有权移交和平台创建邀请码见 [FS-0028](0028-platform-invites-and-ownership-transfer.md)。成员认证/岗位模块尚未实现，成员离开后的资格暂停联动同样未交付。
- 候选人检索无独立限流，仅靠管理权限、2 字符下限、10 条上限和审计约束；若出现滥用需另行增加限流（见 ADR 0032）。
- 「我的组织」默认只读取第一页（`pageSize=100`）；分页参数已预留，界面尚未提供「加载更多」，组织数超过 100 时需后续接入。收件箱只展示第一页（20 条）中仍待回应的邀请。

## 18. 所有正式成员可查看成员名单

- 组织工作区对所有正式成员显示唯一的「成员」标签，不再由 `canManage` 截断；无角色普通成员、认证员、组织者和负责人均可进入。待审核申请人无此入口。
- `GET /organizations/:id/memberships` 实时检查本组织正式成员关系。无管理能力的正式成员仅可读取 `active` 名单，关键词、总数和分页均在 SQL 中按同一条件计算；不能通过查询参数扩大范围。管理者与平台非成员审计账号保留既有申请/历史读取，平台兼任正式成员时遵循普通成员范围，见 [ADR 0038](../decisions/0038-member-roster-read-access.md)。冻结/解散组织的既有正式成员仍可只读，退出/移除后下次读取立即拒绝。
- 普通成员看到「成员名单」及静态名单行，可检索与分页，没有联系方式入口及批准/驳回/移除按钮；管理者仍看到「成员与入会申请」及原有操作。能力取名单接口返回的 `canManage`，状态层亦拒绝无能力的管理提交；API 对邀请、联系方式和写入的独立授权不变。
- 没有新增接口载荷、迁移、依赖、缓存或离线队列；契约补充读取语义。读取继续使用已有骨架、失败重试和 `membership.queried` 同事务审计。
- 验证：全量快速测试 122 文件、737 项通过；补充四种角色标签矩阵后，该测试文件 14 项亦全部通过；组织成员真实 PostgreSQL 集成 1 文件、9 项通过，覆盖普通成员正式名单、申请/历史排除、关键词/计数/分页、越权、冻结只读和成员结束后失权。`pnpm typecheck`、用户端生产构建、`test:styles` 通过，Impeccable 检测无发现。构建 JS 合计 1,389,871 bytes、CSS 56,213 bytes；本轮未采集改动前基线，且工作区存在并行认证改造，不声明体积差值。
- 浏览器：本机开发服务器，当前负责人会话；仅在验收标签页用 `fetch` 替身模拟无角色正式成员与 `canManage=false`，没有变更真实账号或业务数据。320×800 与 1280×900 下可见「概览 / 本组织认证 / 成员」，四行名单无联系资料或移除按钮，320px 无页面横向溢出，标签与搜索按钮均高 44px；搜索无匹配与清空恢复已验证。移除替身并刷新后，真实负责人视图仍有全部管理标签、4 个联系方式入口和 3 个移除按钮。
- 限制：浏览器不是普通成员真实登录，后端安全范围由真实 PostgreSQL 测试验证。CDP 点击及键盘未触发页面事件，交互以 DOM `click()` / `requestSubmit()` 替代，未声明指针或键盘验收通过。后台标签动画帧暂停，视觉核对以 `matchMedia` 替身模拟 reduced-motion 后完成；未覆盖真实系统 reduced-motion、主题切换、中间断点、浏览器多页翻页、弱网与真机。
- 交付自检：业务 SQL 仅 Repository，端口无驱动类型，读取/授权/审计共用事务，参数化查询与现有组织行锁不变；无新表或领域规则。Vue 文件均低于 230 行，无内联 HTTP、跨应用依赖、Naive UI 类型泄漏、Router/Pinia 或持久化改动；沿用集中 token 与静态 Tailwind，无新 CSS、色值、渐变或重要性覆盖。原有写入反馈、二次确认及 API 门禁不变；新只读入口复用现有加载/错误恢复。新权限分支及投影均有测试；无需新增事务适配、迁移或对象存储测试。注释与规格同步，无无主 TODO，浏览器未覆盖项如上明确保留。
