# FS-0007：管理端设计与分阶段实施规格

- 状态：第一批基础与 Naive UI Admin 源码迁移已实施；待真实授权账号端到端验收；业务模块待依赖就绪后实施
- 业务依据：[MVP-001](0001-mvp-scope-and-business-rules.md)、[FS-0002](0002-mvp-platform-feature.md)
- 决策：[ADR 0016](../decisions/0016-admin-web-foundation.md)（首批基础）与 [ADR 0017](../decisions/0017-admin-template-selection.md)（现成模板选型，替代自研应用壳方向）
- 开发入口：`.scratch/admin-console/spec.md` 与 `issues/` 的独立 tickets
- 统一工程约束引用[编码规约](../agents/coding-standards.md)，视觉引用[共享 FIBA UI 规格](../ui/fiba_about_ui_specification.md)，此处不另建规约或 token。

## 1. 目标与非目标

建立平台运营人员的独立管理工作区，覆盖组织治理、平台认证、内容考试、阅卷、社区治理及审计的稳定入口；按 API 成熟度逐步形成真实闭环。首批必须能够构建、部署、登录并查询已存在的审计 API。

不实现全平台业务后端、不新增任意角色编辑器、不把平台管理员伪装成组织者、不实现 AI 审核、聊天、支付、服务器媒体中转和转码。工作台不是虚构增长看板；无统计 API 时不显示假数字、假趋势或“0 待办”。

## 2. 调研与模板采用

需求方明确要求直接使用现成后台模板，停止自研后台基础框架。按 [ADR 0017](../decisions/0017-admin-template-selection.md) 采用 [Naive UI Admin](https://github.com/jekip/naive-ui-admin) 的 **MIT 开源版 v3.0.0**，固定 commit `c9db4cde447240eaa17fbe439f507680819add3d`；完整 GitHub 搜索范围、36 项候选对照、13 项深入核查与取舍均在该 ADR 维护。

迁移必须直接复用上游布局、导航、顶栏、移动菜单和适用的基础页面/组件，替换现有自研应用壳，不接受只参考截图重新仿写。品牌与主题仍适配共享 FIBA 规格；上游源码接入遵循统一编码规约，具体适配范围见 ADR 0017，不另建后台技术规范。

模板不等于现成的裁判业务系统。既有 Cookie 会话、真实审计查询和第 3–6 节业务/安全行为保留；移除演示账户、生产 Mock、假统计及凭据持久化，不新增模板配套后端或动态菜单权限服务。未实现模块继续明确待接入，不以模板的示例 CRUD 冒充业务完成。

源码替换已由 ticket 07 实施，实际装配模板 layout、Header、Menu、Main、Logo 与移动 Drawer；来源及本地裁剪见[第三方说明](../../apps/admin-web/third-party/naive-ui-admin/README.md)。首批“只借鉴、不引入”的方式已被本节和 ADR 0017 替代；第 8 节为迁移前基线，本次结果单独记录在[模板迁移验收记录](0007-admin-template-acceptance.md)，真实授权账号链路仍待补验。

### 2.1 视觉与结构

以下是共享视觉和业务信息结构约束，不要求保留原自研壳的 DOM 实现。模板现成布局应在集中主题与配置中适配，避免重新开发一套布局。

色彩和字体全部消费共享规格：暖白画布、沙金导航区域、白色内容面、炭黑主操作、球场红强调；使用系统字体，无 CDN 字体。页面标题 24–32px，正文优先 14–16px，不用低对比度辅助灰承载必要信息。

```text
桌面（lg 起）
┌──────────────┬──────────────────────────────────┐
│ 裁判工具平台 │ 平台管理 / 当前模块      会话/退出 │
│ 运营         ├──────────────────────────────────┤
│   工作台     │ 标题、业务范围、接入状态           │
│   组织/认证  │ 筛选表单 / 当前结果数 / 操作        │
│ 内容与考试   │ 列表或流程说明                    │
│   内容/阅卷  │ 错误与重试 / 空状态 / 分页         │
│ 安全与治理   │                                  │
│   社区/审计  │                                  │
└──────────────┴──────────────────────────────────┘
手机：顶栏 + 菜单按钮 → 模态菜单；内容单列；审计摘要卡片代替宽表格。
```

采用紧凑操作留白而非营销页面 `py-20`；必要信息采用正文色，这是与工作台一致的窄范围密度/对比度例外。其他颜色、胶囊按钮、圆角、焦点与动效仍遵循共享规格。首页不加装饰图表、远程图片或无语义图标。

## 3. 路由、角色和页面边界

生产路径统一 `/admin/`，静态路由（不依赖角色动态生成）：

| 路由 | 页面与首批行为 | 后续授权/依赖 |
| --- | --- | --- |
| `/login` | 邮箱密码登录、会话恢复；可从裁判端已有 Cookie 进入 | `/auth/session`、`/auth/login/password` |
| `/` | 运营工作台；显示真实会话及模块接入状态，不显示业务计数 | 后续待办聚合须独立定义契约 |
| `/organizations` | 组织治理工作流说明，明确待接入，无伪列表 | platform_admin；FS-0002 Task 7 |
| `/certifications` | 平台认证及申诉步骤，待接入 | platform_admin/指定 reviewer；Task 8 |
| `/content` | 资料、题库与考试版本流程，待接入 | content_editor；Task 9–11 |
| `/grading` | 阅卷范围与改判约束，待接入 | grader；Task 12–13 |
| `/moderation` | 举报、处罚、申诉，标 Beta / 待接入 | moderator；Task 19 |
| `/audit` | 真实平台审计筛选、首批及下一页、重试 | platform_admin；现有 GET 接口 |
| 其他 | 404；返回工作台 | 不将无权限伪装为 404 |

会话 DTO 尚无角色/能力字段，首批导航显示全部流程入口；这不是授权。普通登录用户可看不含私有记录的应用外壳，审计请求由 API 实时拒绝。后续菜单优化需独立能力投影，不得按邮箱、认证级别或审计是否成功推断角色。不提供组织 scope 冒充/切换；组织运营界面另依 FS-0002 的作用域 API 实施。

## 4. 首批可执行行为

### ADM-01：会话与登录

- 初始读取 `GET /api/v1/auth/session`；加载中不发业务请求；401 展示登录；网络失败提供重试，不伪装未登录。
- 邮箱密码登录直接使用现有契约；无公开注册、自动提权或演示账号。验证码登录首批仍使用裁判端入口；已建立的同源会话可恢复。
- 字段必填/格式错误只在字段下显示，并聚焦首个无效字段；网络/凭据/频控错误持久显示；失败保留输入，成功清空密码。
- 退出需服务端确认；失败保留会话并显示重试；成功清空内存业务视图。认证请求 `same-origin`、`no-store`，不得写入 localStorage/IndexedDB。
- 受保护读取 401 立即清空会话；403 显示无平台审计权限，保留安全导航；路由不承担 API 授权。

### ADM-02：平台审计

沿用 `packages/contracts/src/audit.ts`，不新增或复制 DTO。

- `GET /api/v1/admin/audit-events` 查询 `scopeType?`、`resourceType?`、`resourceId?`、`limit=20`、`cursor?`；只发送非空筛选，不发送前端自选 actor。
- `resourceId` 输入必须是 UUID，错误不请求 API。作用域/资源类型必须来自契约枚举。筛选为手动提交，不对每次输入自动发敏感读取请求。
- 每页展示动作、时间（本地时区并明确标识）、操作者 UUID、资源种类/UUID、作用域/UUID、理由；不补造操作者实名，不请求 before/after，不渲染 HTML。
- 显示“本页 N 条”，不是全量总数。下一页使用服务端 `nextCursor`；重查从首批开始，不对游标做数学页码转换，不导出全库。
- 请求期间禁用重复查询及翻页；新筛选清除旧游标。切页/刷新失败清空结果并显示错误和重试，保留筛选；不得把失败当空结果。
- 401 清空身份与列表；403 清空列表且展示无权限；网络/5xx 显示失败；成功空数组才展示“无匹配记录”。迟到响应不得覆盖新结果；页面销毁后的响应丢弃。
- 每次读取都会由 API 写入查询审计；不轮询、不预加载下一页、不用此接口探测管理资格。记录只读，无删除/清空入口。

### ADM-03：业务待接入页面

每个页面展示目的、作用域、3–4 步核心流程、待实现依赖及下一步。不以 disabled 假按钮伪装功能，不发不存在的 API，不显示示例人员/证书/答卷/处罚。工作台入口和深链接可正常导航，展示待接入不表示通过业务验收。

## 5. 后续业务切片与 API 缺口

FS-0002 已规定写接口，但很多后台列表/详情尚未定义，不能用前台接口读取未发布内容。下列 GET 为**待设计契约，不是现有 API**，应与对应后端 ticket 一起评审 contracts、权限、分页、最小投影后实现。

| 切片 | 列表/详情缺口（建议路径） | 写用例与验收重点 |
| --- | --- | --- |
| 组织治理 | `GET /admin/organizations`、`/{id}`；审核资料目的限定 | review/freeze/ownership-transfer；理由、确认、409 重载；不覆盖并发状态 |
| 平台认证 | 已规划 review-queue；补详情与申诉队列/详情 | decision/revoke/appeal decision；不得自审；私有材料临时 URL；撤权停止新读取 |
| 内容考试 | `GET /admin/learning/assets`、`/admin/questions`、`/admin/exams` 及详情 | 草稿/新版本/发布/下线；不可变版本、媒体 available、完整性校验；分类最多三级 |
| 阅卷 | 已规划 `/grading/queue`；补授权答卷与评分说明详情 | 按满分评分、评语、expectedVersion；提交即生效；管理员改判保留原分与理由 |
| 社区治理 Beta | 举报/处罚/申诉队列和受限详情 | hide/restore/mute/ban；时长/理由、确认、审计、申诉回避；不查看认证原件 |
| 账号/媒体策略/规则参数 | 后续独立列表、策略版本及权限契约 | 不在首批放置万能设置页；参数新版本不改历史会话 |

所有确认弹窗都必须明确资源、影响、理由和取消；409 保留可恢复输入并要求读取最新状态，不自动覆盖重试。写操作不能在离线队列中静默执行。媒体仍采用浏览器直传和短时读 URL，API 不处理字节；未确认对象可用前不能发布。

## 6. 状态、响应式与可访问性验收

- 320/375/768/1100/1440px 无页面级横向滚动，长 UUID 和长理由可断行；桌面双列或列表信息，手机单列卡片。
- 导航项和按钮至少 44×44px；有当前页 `aria-current`、跳至主内容链接、可访问字段标签和可见 focus。关闭移动菜单后恢复触发按钮焦点；Escape 关闭且焦点不逃出模态层。
- 每个视图有明确 h1；路由变更后将焦点移至主内容，关闭菜单时不误聚焦背景。加载用文字反馈；错误持久可读且有重试；不依赖红/绿区分状态。
- 系统 reduced-motion 下不保留明显过渡，不远程加载字体或动画。无数据状态不宣称“全部处理完成”。
- 不注册 Service Worker；离线请求显示连接失败，不展示陈旧私有缓存，不提示操作成功。共享设备退出后不残留审计记录。

## 8. 验证记录

> 本节保留模板迁移前的首批自研壳基线。ticket 07 的构建、体积、源码/许可检查及浏览器结果见[模板迁移验收记录](0007-admin-template-acceptance.md)，不能沿用本节数字或截图宣称新模板已验收。

### 8.1 首批检查结果

- 管理端 5 个测试文件、24 项单测通过；`typecheck`、生产构建、`test:styles` 通过。样式检查验证八档断点、语义 token、状态工具类与扫描边界，无默认调色板/Preflight 混入。
- Docker 测试容器限制 300 MB、V8 heap 192 MB；管理端单测实测 cgroup 峰值 147,189,760 bytes（约 140.4 MiB）。同一限制下全仓快测 37 文件、202 项通过；不含独立 PostgreSQL 集成测试。
- 首次新增无旧版管理端可比较：生产 CSS 9.65 kB（gzip 2.64 kB），入口 JS 273.37 kB（gzip 95.34 kB），Input 共享块 43.81 kB（gzip 13.35 kB），审计懒加载块 10.33 kB（gzip 4.46 kB），登录块 3.99 kB（gzip 2.03 kB）。未引入图表、额外 UI 框架、CDN 或生产前端进程。
- Docker `web` 镜像构建通过，`nginx -t` 通过。使用独立验收容器（8444）验证 `/admin` 相对重定向保留映射端口、`/admin/` 和 `/admin/audit` 返回管理端入口、缺失指纹资源返回 404、实际 CSS 返回一年 immutable 缓存、入口返回 no-cache。未替换正在运行的 8443 服务。
- 真实 API 匿名 `/auth/session` 与 `/admin/audit-events` 均返回 401。本次未创建或提升管理员，也未使用用户凭据执行真实登录和审计查询，因此不宣称真实授权读取与数据库审计事务已端到端通过。
- 独立本地 API 替身下验证：登录必填校验关联字段并聚焦、错误密码保留输入且提示凭据错误、成功登录、审计成功/空数据/403/503/加载/下一页末尾、退出失败、401 后销毁受保护列表。替身文件仅在忽略的 `.cache/`，不进入生产产物。
- 320、375、768、1100、1440px 审计布局无页面级横向溢出，长 UUID/理由正常换行；按钮/输入/筛选至少 44px。桌面工作台及 320px 移动菜单完成截图视觉复核。
- 移动菜单支持焦点约束、Shift+Tab、Escape；关闭回触发器，导航后定位主内容。横屏 667×375 菜单在视口内滚动；系统 reduced-motion 仿真下实际过渡时长为 0.01ms。localStorage 空、Service Worker 注册数为 0。

### 8.3 后续验收限制

组织/认证/内容考试/阅卷/社区治理仍待接入；无可用统计接口所以没有待办总数。真实管理员身份与审计写入的一致性需在受控 HTTPS 环境使用授权测试账号继续验收。未重复执行独立 PostgreSQL 集成测试（本次未改后端）；浏览器替身测试不能替代该检查。当前只支持共享浅色主题，不宣称实现暗色主题或完整 PWA。
