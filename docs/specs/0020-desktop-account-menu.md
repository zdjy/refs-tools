# FS-0020：裁判端桌面账号菜单与账号入口页

- 状态：已实施，自动化与浏览器验收记录见 §7。
- 适用应用：`apps/referee-web`。
- 业务依据：[FS-0006 首页与模块导航](0006-home-navigation.md)（一级导航、身份投影与建设状态规则的唯一来源）、[MVP-001](0001-mvp-scope-and-business-rules.md)。
- UI 依据：[共享 UI 规范](../ui/macos_fiba.md)、[响应式规格](0005-responsive-layout.md)。
- 工程约束：遵循[统一编码规约](../agents/coding-standards.md)，不在本文重新定义依赖、分层、样式或文件长度规则。

## 1. 背景与目标

FS-0006 首版把「我的」放在一级导航末位并直达 `/account`，桌面顶栏因此多出一个与账号身份重复的入口。本次改版：

1. 桌面主导航去掉「我的」，一级导航只保留首页、学习、工具、社区。
2. 顶栏最右侧的用户名成为账号入口：点击展开菜单，承载个人入口与退出登录。
3. 账号菜单中的每个入口都必须落到真实页面；尚未实现的页面明确显示建设状态，不提供虚假操作。

移动端（小于 `tablet`）继续使用底部主导航，「我的」保留在底栏，不与桌面账号菜单重复。

## 2. 范围

### 2.1 本次交付

1. `primaryNavigation` 保留五项供移动底栏使用，新增 `desktopNavigation` 供桌面主导航使用（不含 `account`）。
2. 新增账号菜单：`我的主页` → `/me`、`我的组织` → `/organizations`、`账号设置` → `/account`、`意见反馈` → `/feedback`，分隔线后为 `退出登录`。
3. 新增 `/me` 与 `/feedback` 两条静态路由，复用现有「建设中」说明页形态。
4. 退出登录在菜单内触发二次确认；失败保留当前登录态并给出提示。
5. 菜单的键盘、焦点、`aria` 语义与 44×44px 触控目标。

### 2.2 明确不做

- 不实现个人主页、反馈工单、通知中心、主题切换或会员/等级体系；参考图里的这些元素不在本次范围。
- 不新增后端接口、数据库表、跨端 DTO 或持久化；`/me`、`/feedback` 是纯静态说明页，无需登录即可阅读。
- 不修改移动底栏的栏目顺序、工具扇形菜单（见 [FS-0019](0019-mobile-tools-fan-menu.md)）或工作台布局。
- 不把登录成功后的落点从 `/account` 改为其他页面。
- 不为账号菜单建立 Pinia store；展开状态属于界面状态，留在组件与交互 Composable 内。

## 3. 交互与信息架构

| 位置 | 行为 |
| --- | --- |
| 桌面主导航（≥ `tablet`） | 首页 `/`、学习 `/learning`、工具 `/tools`、社区 `/forum`；不再包含「我的」 |
| 移动底栏（< `tablet`） | 保持五项，含「我的」→ `/account` |
| 顶栏右侧（已登录） | 用户名按钮：显示名首字符圆标 + 显示名 + 展开指示；点击展开账号菜单 |
| 顶栏右侧（未登录/加载/失败） | 维持原有登录、注册与重试入口，不显示账号菜单 |
| 账号菜单项 | 我的主页、我的组织、账号设置、意见反馈；分隔线后为退出登录 |

- 菜单顺序固定，不按使用频率排序；`我的组织` 与 `账号设置` 分别是组织事务与账号安全两个不同目的地，不合并。
- `我的主页` 与 `意见反馈` 当前是建设说明页，页面必须写明「建设中」及后续范围，不显示「立即编辑」「提交反馈」等无效按钮。
- 菜单头部只显示公开显示名与「裁判账号」标签；不投影邮箱、会话有效期或服务端错误详情，避免把私密字段带进常驻导航。
- 退出登录通过确认弹框执行，文案说明本地比赛记录仍保存在当前设备；确认后调用既有 `logout`，失败时保留登录态并提示重试。
- 菜单关闭后不改变当前页面，不触发导航。

## 4. 路由合同

| 路径 | route name | 页面形态 | 一级导航归属 |
| --- | --- | --- | --- |
| `/me` | `profile` | 建设说明（个人主页） | 我的（仅移动底栏高亮） |
| `/organizations` | `organizations` | 建设说明（既有） | 无 |
| `/account` | `account` | 现有账号与安全页 | 我的（仅移动底栏高亮） |
| `/feedback` | `feedback` | 建设说明（意见反馈） | 无 |

- 菜单路径与标签来自 `src/navigation/account-menu.presentation.ts` 与 `modules` 的同一导航定义，不在组件里另写字面量路径。
- 路由仍为显式静态声明与懒加载，不按角色动态注入，不做通配模块路由。

## 5. 可访问性与键盘

- 触发按钮：`aria-haspopup="menu"`、`aria-expanded`、展开时 `aria-controls` 指向面板 id，可访问名称包含显示名与「账号菜单」。
- 面板：`role="menu"` 与可访问名称；每项 `role="menuitem"`，行高不小于 44px；退出登录是命令而非链接。
- 键盘：Enter/Space 打开后焦点进入首个菜单项；`ArrowDown`/`ArrowUp` 循环移动，`Home`/`End` 跳到首尾；`Escape` 收起并把焦点还给触发按钮；Tab 离开面板或点击外部同样收起。
- 鼠标打开不抢焦点，避免在鼠标操作后弹出多余的焦点环；键盘打开必须有可见焦点环。
- 确认弹框关闭（确认或取消）后焦点回到触发按钮；弹框内按钮具备可访问名称。
- 状态不能只靠颜色表达：展开状态由 `aria-expanded`、箭头旋转与面板可见性共同表达。

## 6. 视觉与样式

- 面板为纯色 `surface` 卡片、1px `line` 边框、`rounded-2xl`、`shadow-lift`；不使用渐变、深色毛玻璃、发光或大于 1px 的边框，不套用参考图的深色配色。
- 触发按钮为胶囊形，与顶栏其他控件的圆角、过渡（200ms `ease-out`）和按压反馈一致。
- 退出登录使用球场红文字，仅作破坏性动作提示，不新增第三套配色。
- 面板宽度固定并受 `100vw - 32px` 约束，320px 起不产生页面级横向溢出；菜单不遮挡底栏主导航的点击区域。

## 7. 验收记录

自动化：

- `router.test.ts`：桌面主导航为四项、移动主导航仍含「我的」、账号菜单四项标签与路径均可解析到真实路由；新增模块的 `moduleId` 与 `/me`、`/feedback` 路由一致。
- `typecheck`、`test`（20 个测试文件）、`test:styles`、生产构建通过。

浏览器（`https://localhost:8443`，合成账号）：

- 桌面 2048px：主导航只剩四项，用户名按钮位于最右侧；点击展开菜单，五个菜单项与分隔线渲染正常，鼠标打开无多余焦点环。
- 键盘：焦点在按钮时 Enter 打开并聚焦「我的主页」，方向键、Home/End 移动正常，Escape 收起且焦点回到按钮；点击外部收起。
- 菜单项分别导航到 `/me`、`/organizations`、`/account`、`/feedback`；两项建设说明页显示「建设中」与相关入口。
- 退出登录弹出确认框，取消后关闭且焦点回到触发按钮。
- 375px 移动端：底栏仍显示「我的」，菜单面板宽 264px、右对齐、无页面级横向溢出；960px 断点下桌面主导航与账号菜单同时可用，顶栏无横向溢出。
