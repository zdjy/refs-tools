# ADR 0033：裁判端采用「场边」版式基线，配色沿用 macos_fiba

- 状态：已接受
- 关联：[ADR 0020](0020-macos-vibrancy-ui-baseline.md)、[ADR 0013](0013-tailwindcss-styling.md)、[ADR 0031](0031-offline-app-shell-service-worker.md)
- 替代：ADR 0020 中关于裁判端版式、圆角与阴影的部分；配色仍以 [`macos_fiba.md`](../ui/macos_fiba.md) 为准；管理端不受影响

## 背景

用户要求使用 tasteskill 重新设计裁判端前端。设计过程经历了几轮调整：先试暖纸色，再试参考 iOS 的灰底系统蓝，随后加入彩色图标块、渐变和色晕；最后用户明确要求尽量不用渐变、配色回到 `macos_fiba.md`，其余保留，并增加细节、重排组件。本 ADR 记录最终结果，中间方案不再保留。

tasteskill 面向营销官网（静态 HTML 与自带 `system.css`），不能原样套用到 Vue 应用。本次只采用与应用相通的原则：单一系统、统一的按钮与圆角、文案直述、动效只做悬停与按压反馈。

## 决策

1. 配色以 `macos_fiba.md` 为唯一来源，`ui-theme.test.ts` 逐项断言 `ui-tokens.ts` 与之一致。只用色板内颜色，不新增色相。
2. 版式与动效见 [`docs/ui/courtside.md`](../ui/courtside.md)：大标题、细线分隔的平铺列表行、桌面左侧导航栏、沙金选中胶囊加红点、弹性曲线、挂载浮入、弹出与展开动画。
3. 内容区块不套白色圆角卡片，用 1px 细线分段；圆角只留给浮层、输入控件、图标块和登录面板。核心页面（社区、学习、工具、模块说明、登录注册）已按此改完。
4. 不使用渐变、色晕与高光层。质感来自细线节奏、毛玻璃导航、背景线稿动效与交互动效。
5. 废除 `macos_fiba.md` 的动效禁令（含“严禁装饰性跳动动画”），允许装饰性与氛围动效。保留的约束：不引发布局位移、持续运行的动效必须能被用户关闭、优先只动画 `transform` 与 `opacity`，以及系统“减弱动态效果”的可访问性要求。骨架屏随之放开为透明度呼吸，见 ADR 0030 与 FS-0025；其 300 ms 延迟与读屏规则不变。
6. 增加背景动效：右上半场线稿与一枚沿抛物线投篮的小球及篮筐涟漪，左下一枚间歇吹响（晃动加声波）的裁判哨子，纯色、无渐变。细节与约束见 `courtside.md` §7：全部运动只改 `transform` 与 `opacity`，小球拆成两层元素合成抛物线而不用 `offset-path`；背景从侧栏右侧开始，避开毛玻璃侧栏；可由开关暂停，偏好存 `localStorage`，默认开启。
7. 手机端（`tablet` 以下）的论坛版块改用左侧抽屉：搜索栏左侧 44×44 的三条横线按钮唤起 `NDrawer`，按钮与搜索栏同处一行，当前版块名由结果计数行表达；抽屉内列出各版块、说明与讨论数，选中项用沙金底与 `aria-current`；平板及以上隐藏该按钮并保留横向胶囊筛选。版块计数由 `boardCounts()` 从数据统计，不手写。
8. 色板只有一个红色，错误态复用 `accentHover`，不另立危险色；原 `red` / `redHover` 改名为 `accent` / `accentHover`，使类名与语义一致。
9. `muted`（`#8C867E`）在画布上只有 3.4:1，仅用于占位符与图标；真实文字改用 `body`。红色文字用 `accentHover`。
10. 主按钮回到色板规定的墨底白字；红色只用于强调、色点与焦点。
11. 模块图标块限定在红、金、绿、墨、沙五种，金与沙底配墨色图标（白色在金上只有 2.38:1）。
12. 字体栈优先 `-apple-system`，回落到苹方等系统字体；不加载远程字体，也不打包字体文件。
13. 本次重做全局视觉层与核心页面（社区、学习、工具、登录注册）；其余页面继承新 token，仍使用旧圆角与边框卡片的页面留待逐页整理。

## 备选方案

- 直接使用 tasteskill 的 `starter.html` 与 `system.css`：与 Vue、Naive UI、Tailwind 的工程边界冲突，官网版式也不适合高频操作页面。
- 在色板上拓展出陶土、琥珀、橄榄等板块色：违背“配色回到 macos_fiba”的要求，且金色等新增色相难以同时满足图标对比度。
- 保留渐变但避开蓝紫：用户随后要求尽量不用渐变，因此整体取消。
- 打包 SF Pro 或自有中文字体：SF Pro 授权不允许随网页分发；中文字体子集化需要内容清单与流水线，并占用 ADR 0031 的预缓存体积上限。

## 后果

- 视觉与交互取值在本 ADR、`courtside.md`、`macos_fiba.md` 与[样式规约](../agents/coding-standards/styles.md)中维护；ADR 0020、FS-0012 等历史文档的措辞不回改。
- 红色填充配白字为 4.62:1，仅对粗体或大号文字达标；小号红色文字必须用 `accentHover`。
- 非 Apple 设备上 `-apple-system` 不可用，会回落到苹方或系统中文字体。
- 背景动效的性能用无头 Chrome 经 CDP 实测（Tracing 汇总各线程 8 秒内的忙碌时间）。主线程几乎无开销：开启后 5 秒内多约 10 ms，无长任务。合成器线程的开销来自“有动画持续出帧”，与具体画了什么关系不大：哨子连续摆动单独就占全部开销的绝大部分。哨子改为间歇晃动后，手机视口、4 倍 CPU 降速下，Renderer 合成器约降 25%，Viz 合成器与 GPU 主线程各约降 40%。
- 手机顶栏、底栏的 backdrop-blur 在同条件下实测：去掉模糊后 Viz 约降 25%、GPU 主线程约降 45%，因此模糊有可见代价，但没有删除，以保持材质。
- 以上测量的局限：无头 Chrome 不受垂直同步限制，帧率约 165 Hz，绝对耗时约为 60 Hz 真机的 2.7 倍，只能用于比较相对差异；GPU 为软件渲染，不代表真机的 GPU 占用；没有在真机或低端手机上量过帧率与电量，开关是兜底。
- 实测中发现并修复了一个缺陷：背景层原先在手机宽度下被压成零宽并被裁掉，手机上背景动效从未显示。修复后手机上才真正渲染。
- 线稿压低了对比度并位于文字之下，但文字与线稿重叠处的可读性只做了目视检查，没有逐页量化。
- 组织、阅读、工作台、账号设置、区位码、404 等页面已去卡片化（区块改为细线与左侧竖线）。逐页验收用的是 DOM 扫描（计算样式中 ≥8px 圆角且带底色、边框或阴影的区块），不是视觉截图，因此只能保证没有残留卡片，不能保证版式好看。扫描发现并清除了工作台遗留的 5 个 `n-card`。
- 保留圆角的位置：弹窗与菜单、输入框、图标块、按钮与筛选胶囊、登录面板、页内更新提示、阅读页的封面图。
- 选中胶囊的滑动依赖模块级变量记录上一次位置，因为各页面独立挂载导航外壳；根治方案是把外壳提到路由层，改动面较大，未纳入本次。
- 未改版页面可能短期内混用旧圆角与新版式，需要后续排期逐页处理。
- 不引入新依赖，产物体积预期不增加。
