# ADR 0019：裁判端引入 Motion 动画库与模拟论坛内容

- 状态：已接受
- 关联：[FS-0011](../specs/0011-portal-motion-and-simulated-forum.md)、[ADR 0018](0018-editorial-content-and-icons.md)、[FS-0008](../specs/0008-editorial-home.md)

## 背景

用户要求裁判端首页参照 Awwwards 案例，内容更丰富（论坛帖子、学习资料等），不再只是功能入口卡片，同时共享 UI 规范不变（后由 ADR 0020 切换为 macOS 毛玻璃规范）。用户明确选择：允许使用开源动画库且不限制动效；论坛采用完整模拟信息流；素材用原创 SVG。

FS-0008 与 ADR 0018 对此有三处限制：禁止视差与持续自动播放；禁止虚构作者、头像、热度与回复数；不引入重型动效库。本决策在窄范围内放宽这三点，并写明边界。

## 决策

1. **动画库**：`apps/referee-web` 增加 `motion@14.9.0`（MIT，精确版本），仅使用其框架无关的 `animate`、`inView`、`scroll`。动效适配层放在 `src/components/ui/motion/`，不含业务逻辑。
2. **范围**：只用于首页与阅读页，随这两个路由的懒加载 chunk 加载，不进入工作台、认证页或主入口 chunk。
3. **无障碍守卫**：系统开启 reduced-motion 时，入场、滚动联动与跑马灯一律不启动，内容保持默认可见。入场动画的元素默认可见，仅在脚本挂载成功后才设初始透明度为 0，脚本失败时内容不会永久隐藏。持续滚动的关键词带必须提供暂停按钮。
4. **模拟论坛内容**：随应用发布的静态示例，位于 `src/content/threads.sample.ts`。允许示例角色（仅角色称谓）、叙事性时间描述和固定的“觉得有用”示例值；每处均标注“示例”。仍然禁止真实姓名、头像图片、真实时间戳、浏览量、排名、热门标记和发帖、回复、点赞能力。
5. **视觉**：不修改当时的共享 UI 规范、token 与断点（视觉基线后由 ADR 0020 替换）。不使用渐变、重阴影、emoji；所有图标为 Lucide，封面为原创 SVG 纯色几何。

## 备选方案

- 纯 CSS 动效：零依赖，但滚动联动与错落入场需要大量手写样式，违反样式规约“不用整页手写 CSS”的倾向。
- GSAP：功能更全，但许可条款较复杂，体积更大。
- 仅沿用 FS-0008 不放宽：无法满足用户对 Awwwards 级表现力的要求。
- 完全虚构的真实感信息流（昵称、日期、浏览量）：风险是被误认为真实数据，不采用。

## 后果

- 首页与阅读页 chunk 增大，见 FS-0011 的体积记录。其余路由不受影响。
- 示例内容的“示例”标注是真实性的唯一防线，单测约束字段集合与时间格式。
- 真实论坛上线时，`threads.sample.ts` 由受保护 API 取代；示例角色与示例值随之删除，不迁移为真实数据。
- 若后续要放宽到工作台等操作页，需要单独决策：场边操作页不应承载入场动画。
