# ADR 0030：弱网判定、读请求自动重试与加载反馈

- 状态：已接受
- 关联：[ADR 0023](./0023-alova-http-client-and-ddd-gateway.md)、[ADR 0020](./0020-macos-vibrancy-ui-baseline.md)、[FS-0024](../specs/0024-operation-feedback.md)、[FS-0025](../specs/0025-network-resilience-feedback.md)、[前端规约 §5–§6](../agents/coding-standards/frontend.md#6-弱网与加载反馈)

## 背景

FS-0024 补齐了操作结果的 toast，但没有定义"请求很慢""断网""超时"时用户应看到什么。排查现状：

- 加载状态只是各页面一行静态文字或按钮 `loading`，没有区分「刚开始」「较慢」「长时间无响应」。
- 平台请求超时固定 15 秒，超时与断网都归一为 `HttpError('network')`，文案无法区分"请求根本没发出"与"发出后无响应"。后者对写操作意味着服务端结果未知。
- 离线只在管理端三个页面有局部 `NAlert`，裁判端没有任何离线提示；离线时重试按钮仍会发出注定失败的请求。
- 读请求遇到瞬时抖动（一次丢包、一次 503）必须由用户手动重试。
- 项目是弱网场景为主的场边工具，生产主机仅 2 核 2 GB（根级 `AGENTS.md`），不宜为"更准确"的探测增加服务端负载。

## 决策

### 1. 弱网判定：以请求耗时分级，联网状态取自浏览器

不依赖 Network Information API（Safari 不支持），也不引入心跳探测接口。判定只用两个来源：

- `navigator.onLine` 与 `online` / `offline` 事件。`false` 可信（确实离线），`true` 不保证可达。
- 在途平台请求的耗时，由请求监视器记录。

| 档位 | 条件 | 反馈 |
| --- | --- | --- |
| online | 无在途请求，或最早的在途请求不足 3 秒 | 无 |
| slow | 最早的在途请求 ≥ 3 秒，或有读请求正在自动重试 | 网络较慢提示 |
| stalled | 最早的在途请求 ≥ 8 秒 | 长时间未响应提示，页面给出重试入口 |
| offline | 浏览器报告离线 | 持续的离线提示；请求不发出 |

阈值集中在 `networkPolicy`（两端各一份，内容一致），不得在页面中散落魔法数字。

### 2. 传输层行为

在 `PlatformClient` 内加入请求守卫，而不是新增一层：

- **离线直接拒绝**：不发出请求，抛 `offline` 类 `HttpError`（管理端为 `code: 'OFFLINE'`），网关翻译为 `OFFLINE` 错误码。与 `network`（请求已发出后失败）区分。
- **只对 GET 自动重试**：最多 2 次，指数退避（500 ms 起、上限 4 s）并取 50%–100% 抖动，总预算 30 秒。只重试传输失败与 502 / 503 / 504；4xx（含 429）、响应无效不重试。重试等待期间转离线则停止。
- **写操作（POST / PATCH / DELETE）永不自动重试**。超时或断开后服务端可能已处理，自动重试会重复写入。失败文案明确提示"先刷新确认是否已生效"，把判断交给用户。
- **不做离线写入队列**。AGENTS.md 要求先定义缓存数据范围、冲突策略再实现同步；本 ADR 不引入。离线时写操作被拦截并明确提示"未提交"，输入保留。
- 请求监视器只保存在途数量、开始时间、重试标志和最近结果，不记录 URL、请求体或响应，与"不缓存私有响应"一致。
- 对象存储直传（`ObjectStorageClient`）不受守卫影响，仍由 `AbortSignal` 取消，重试由上传状态机控制。

### 3. 加载形态按场景选择

| 场景 | 形态 | 理由 |
| --- | --- | --- |
| 提交 / 保存（按钮触发） | 按钮内 loading 并禁用，慢速阶段在按钮旁补一行说明 | 不遮挡已填内容，防重复提交；慢速时明确"请勿重复操作" |
| 首次加载页面主体（资料、会话） | 静态骨架屏，较慢时补说明，长时间无响应出现"重新加载" | 避免布局跳动；骨架与真实内容行高接近 |
| 已有数据的刷新（管理端列表） | 保留旧内容与表格自带 loading，慢速补说明与重试 | 不清空数据，不制造空白 |
| 路由切换（懒加载 chunk） | 顶部全局进度条（Naive UI LoadingBar），延迟 200 ms 出现 | 弱网下 chunk 可能数秒才到 |
| 离线 / 慢 / 卡顿 / 恢复 | 固定在视口底部的全局网络提示 | 不占文档流，不与吸顶导航争位 |

骨架屏为静态纯色块，**不使用脉冲、闪烁或旋转动画**，遵守 UI 基线对装饰性动效的禁令；进度条与提示使用主题 token，无渐变。

所有加载态共用同一时序：**延迟 300 ms 才显示**（快请求零闪烁），**一旦显示至少保持 400 ms**，之后按 3 秒、8 秒升级。该时序由无 Vue 依赖的 `createLoadingPhaseTracker` 实现，可注入时钟与定时器单测。

### 4. 分层与归属

- 阈值、监视器、状态判定、加载时序是无 Vue 依赖的纯逻辑，放在 `src/infrastructure/network/`。
- `useNetworkStatus`、`useLoadingPhase` 与横幅、骨架、提示组件放在 `src/components/ui/`，不引用业务模块。
- 传输层与网关**不调用通知 API**，与 FS-0024 的"状态与表现分离"一致。
- 两端各自维护一份副本，不跨应用引用（`architecture.md` 红线）。代价是维护两份相同的纯逻辑；改阈值须同步两处并更新两端测试。若日后出现第三个前端或副本漂移，再评估抽为独立 workspace 包，届时另立 ADR。

## 备选方案

- **心跳探测接口**：判定更准，但持续占用 2C2G 主机并增加移动端电量，且探测成功不代表业务接口可用。拒绝。
- **写操作带幂等键自动重试**：需要后端为每个写接口支持 `Idempotency-Key`，属契约与后端改动。目前仅媒体意向创建有幂等键。留待后端先行。
- **离线写入队列 + 联网同步**：需要先定义缓存数据范围、冲突展示和队列持久化（AGENTS.md 要求）。范围过大，拒绝。
- **在传输层直接弹 toast**：违反 FS-0024 的状态与表现分离，并会为同一失败重复通知。拒绝。
- **骨架屏使用闪烁动画**：违反 UI 基线对装饰性动效的禁令。拒绝。
- **抽共享包 `packages/ui-network`**：`contracts` / `domain` 禁止依赖 Vue，而该包含 Vue 适配；仅抽纯逻辑又会让两端形态不一致。当前规模下复制更简单。

## 后果

- 读请求在抖动网络下成功率提高，但最坏情况下一次失败的读取会多等约 2–6 秒（两次退避加两次尝试），错误出现更晚。该取舍可接受，且用户在重试期间能看到"网络较慢"提示。
- 写操作超时的文案变长，且要求用户先核对再重试。这是有意的：避免重复写入比省一次点击更重要。
- 离线判定存在已知盲区：处于"已联网但无法到达服务器"（如强制门户 Wi-Fi）时，浏览器仍报告在线，此时靠请求耗时升级为 slow / stalled。
- 每个平台请求多一次监视器写入（计数与时间戳），可忽略。
- 新增的页面需要按前端规约 §6 选择加载形态。
