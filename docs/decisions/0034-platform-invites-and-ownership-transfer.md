# ADR 0034：平台创建组织邀请码与所有权移交

- 状态：已接受
- 范围：[FS-0028](../specs/0028-platform-invites-and-ownership-transfer.md)，完成 [FS-0002 Task 7](../specs/0002-mvp-platform-feature.md) 剩余项
- 关联：[ADR 0025](0025-admin-organization-governance.md)、[ADR 0028](0028-organization-members-and-invitations.md)、[ADR 0032](0032-referee-organization-access.md)、[ADR 0014](0014-scoped-authorization-and-audit-foundation.md)

## 背景

ADR 0025、0028、0032 分期交付了平台审核、成员与成员码，但「平台一次性创建邀请码」「所有权移交」仍未实现，Task 7 无法关闭。FS-0001 §4.3 写明「所有权转移由平台管理员处理并审计」，而需求方明确要求增加**现任负责人发起**的路径。两者存在差异，本 ADR 按需求方的选择记录取舍，不静默覆盖原规格。

## 决策

1. **平台邀请码独立成表**（`platform_organization_invites`），明文前缀 `ro_`，成员码前缀 `rj_`。两类凭据在三层隔离：Schema 正则在 HTTP 入口拒绝跨用途前缀；分表存储使哈希互不可见；兑换用例各自只查自己的表。只存 SHA-256 与末 4 位，明文仅在创建响应出现一次。
2. **一次性且短期**：使用次数固定为 1，有效期 1–7 天（默认 3）。库内 `CHECK` 保证「使用三元组同有同无」「已使用不可撤销」，`used_organization_id` 部分唯一索引保证一码最多对应一个组织。
3. **兑换并入自助申请接口**：`POST /me/organization-applications` 增加可选 `platformInviteToken`，不新增用户端路由。带码时同事务完成「建 pending 行 → 条件 `UPDATE` 消费 → 置 active → 建负责人成员与 owner+organizer 角色 → 审计」。先建组织行是因为使用记录有外键；消费不到则整笔回滚。审核人记为**发码管理员**，行为人仍是申请人，二者在审计与 `reviewed_by` 中分别体现。不占用「待审核 3 个」名额，因为它不进入审核队列。
4. **失败统一为 `PLATFORM_INVITE_INVALID`（422）**，不区分不存在、已使用、已撤销、已过期，避免探测码状态。
5. **所有权移交有两条路径**：
   - 平台管理员直接移交：`platform.manage`、理由必填、组织行版本条件；允许 `active` 与 `frozen`（负责人缺失的冻结组织需换人后才能解冻）；取代仍待处理的负责人请求。
   - 负责人发起、接收人接受后生效：仅 `active` 组织；每组织同时最多一个 pending（部分唯一索引），有效期 7 天，到期不依赖后台任务，读取时投影为 `expired`，新建请求时在组织行锁内落库。
6. **换手共用一个函数**（`swapOwner`）：旧负责人撤销**全部**组织范围角色（含下属赛事、比赛），仅保留正式成员；新负责人获得 owner 与 organizer；`changeOwner` 以组织行版本条件更新并刷新实名与联系方式快照；审计与角色变更同事务。新负责人须为 active 成员、账号有效且账户资料完整（与自助申请一致），发起与生效时各校验一次。
7. **加锁顺序固定为「组织行 → 请求行」**，与成员写入、冻结、撤权一致，避免死锁与陈旧授权。
8. 抽出 `grantOwnerRoles`，审核通过、邀请码直通与移交三处共用，避免重复实现同一不变量；`organizer` 仅在审核/直通时严格冲突，移交时新负责人本就是组织者按已具备处理。

## 备选方案与后果

- **新增 `POST /me/organization-applications/with-invite`**：路径更清晰，但前端要维护两条提交路径，拒绝。
- **邀请码可多次使用**：灵活，但偏离规格「一次性」，拒绝。
- **负责人一步直接生效**：表结构更简单，但误选后只能靠新负责人或平台移交回来，拒绝；代价是多一张表和接收人界面。
- **旧负责人同时失去成员身份**：权限更干净，但会让原运营者无法继续作为普通裁判参与，拒绝。
- **只由平台处理（保持 FS-0001 原文）**：被需求方否决。FS-0001 §4.3 已同步补充说明。

后果：新增迁移 `0010` 与两张表；前端为静态产物，无新增依赖。**不含**：组织解散、通知投递（接收人需回到「我的组织」查看）、认证与选派联动。负责人路径的接收人收件箱仅读取第一页（20 条）。
