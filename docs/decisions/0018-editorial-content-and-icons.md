# ADR 0018：裁判端内置编辑内容与 Lucide 图标

- 状态：已接受
- 关联：[FS-0008](../specs/0008-editorial-home.md)

## 背景

用户要求裁判端从功能入口集合转向包含学习资料和帖子内容的体验，同时保持 FIBA UI 规范。真实学习与论坛 API 尚未接入，用户选择先交付内容型首页与内置阅读；不得把模拟用户数据包装成业务事实。用户同时要求统一 Lucide 图标。

## 决策

1. 公开、自编学习导读与明确标注的讨论示例放在裁判端自有静态内容模块，按应用版本发布。它们不是服务端 LearningAsset、ForumPost 或用户记录，不引入伪造统计、作者和学习状态。
2. 用五条显式懒加载路由提供完整阅读，共享内容配置仅承担前端展示，不新增跨端载荷、后端、持久缓存或同步。真实业务内容后续独立接入受保护 API。
3. 仅在 `apps/referee-web` 添加官方 `@lucide/vue`，按名导入组件，替换该端既有手绘 UI 图标。该包为当前 Lucide 官方 Vue 包；不使用已停止更新的旧包名，不全量注册或动态加载整个图标库。
4. 主视觉使用随应用提供的原创球场 SVG 插图，不作为 UI 图标，也不表达权威站位标准。保留无远程资源依赖的静态部署。

## 备选方案

- 仅放占位内容并链接建设说明：仍无法满足可实际阅读的需求。
- 同步实现真实论坛与学习平台：需要完整发布、审核、授权及存储流程，超出已确认范围。
- 手动复制 Lucide 路径：免安装依赖，但来源、许可及后续维护不如官方按需组件清晰。
- 引入重型渲染或动效库：与本次阅读场景和低资源约束不相称。

## 后果

首页具有真实可读的静态内容，但不意味着学习与论坛业务上线。只增长前端静态资源，不增加生产服务、媒体处理、私有数据缓存或 API 负载。官方图标组件有小量产物成本，需在构建中记录变化。视觉 token、导航边界与工作台状态不变。
