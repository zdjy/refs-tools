# ADR 0028：组织成员关系、定向邀请与实时撤权

- 状态：已接受
- 范围：[FS-0016](../specs/0016-organization-membership.md)
- 关联：[ADR 0014](0014-scoped-authorization-and-audit-foundation.md)、[ADR 0025](0025-admin-organization-governance.md)

## 背景

平台组织审核已建立负责人成员和默认角色，但缺少后续邀请、入会审核和退出机制。成员结束后仅凭 active membership 检查虽然能即时拒绝权限，重新入会仍可能激活旧角色，因此需要明确角色生命周期。

## 决策

1. 成员与邀请继续归 organizations 模块，使用 `0007` 扩展成员版本并新增定向邀请表。成员邀请码与定向邀请是不同概念，本轮不引入明文凭证或邀请码用途复用。
2. 新增单一固定权限 `organization.members.manage`，仅 organization-scoped owner/organizer 可用。平台使用已有 `platform.manage` 审计读取，不能替代组织运营角色；服务端返回 canManage 仅供界面呈现，每次写请求仍重新授权。
3. 成员写入先锁组织行，再读取账号、角色和成员依据；成员和邀请使用版本条件更新。组织内串行化换取简单且可验证的一致性，避免申请、邀请接受、冻结和移除交错时重复建立当前关系。数据库部分唯一索引继续兜底，不新增缓存或基础设施。
4. 邀请到期按服务端当前时间投影为 expired，接受在到期时刻拒绝；新邀请先将旧过期待回应记录转为 expired，保留历史并释放唯一索引。重复同向回应无副作用，反向回应或过期回应明确冲突。
5. 移除与本人退出在同事务结束成员关系，并通过 authorization 端口逐条撤销组织及下属赛事/比赛的绑定、写角色审计。成员重入建立新的历史关系，不恢复管理角色。组织所有者须先走未来的平台移交，不能被普通成员动作移除。
6. 所有变更与读取审计共用事务。读投影只包括昵称、标识、状态与时间，不读取邮箱或实名。当前无通知投递模块，定向邀请通过本人收件箱 API 可见；不把创建邀请表述为邮件已投递。

## 备选方案与后果

- 直接让平台管理员增删成员：扩大为组织超级权限，拒绝。
- 接受邀请即授予组织角色：混淆成员与授权，拒绝。
- 退出只改成员状态、重入自动恢复角色：旧管理权限可能意外复活，拒绝。
- 组织内每个用户单独锁：可提高并发，但与冻结/角色及现有审核协同更复杂，本期不采用。

认证及选派业务尚未实现，后续需接入成员现状与暂停/冻结规则；本期保留历史记录和实时角色撤销，不声明跨模块资格联动已完成。前端仍为静态产物，无新增依赖或运行时服务。
