# ADR 0025：平台组织治理与首次运营授权边界

- 状态：已接受
- 范围：[FS-0015](../specs/0015-admin-organization-management.md)、FS-0002 Task 7 的平台治理首期
- 关联：[ADR 0014](0014-scoped-authorization-and-audit-foundation.md)、[ADR 0015](0015-casbin-authorization-engine.md)、[ADR 0022](0022-admin-user-crud-and-cookie-boundary.md)

## 背景

组织归属骨架已支撑实时授权，但缺少平台审核与冻结入口。组织通过审核时，组织状态、负责人正式成员关系及默认角色必须同时生效，审计失败不得留下部分运营授权。管理端还需要一个可实际录入待审资料的入口，后续用户自助申请和成员流程则尚未交付。

## 决策

1. organizations 模块拥有组织资料和成员写入，通过应用事务端口复用 authorization 的角色写入及 audit 追加端口；身份有效性使用身份模块只读锁定端口。平台治理不通过修改全局授权矩阵实现，不让平台管理员隐式成为组织运营者。
2. 管理端按昵称或邮箱查询并选择已有有效、邮箱已验证的用户代录申请，提交所选 `ownerUserId`，但一律进入 `pending_review`。创建接口不接受手填实名；账号尚无实名档案读取能力，新申请保留历史实名列的空值默认，不从昵称推导实名，已有实名资料继续受保护。平台审核通过后才建立负责人正式成员关系及 `owner`、`organizer` 两条默认绑定；业务变更和角色/治理审计共用同一数据库连接。角色冲突失败时整笔回滚，不覆盖历史授权。
3. 使用新增迁移 `0006` 扩展现有组织表；旧归属骨架保留默认业务字段，迁移不推导认证或角色。平台治理动作使用组织行锁及 `expectedVersion`，纯状态转换由 domain 表达。审核决定及最近治理理由保存在组织资料，完整历史由追加式审计追踪。
4. 冻结保留成员和绑定，由现有实时 scope 授权拒绝新运营。解冻重新核验负责人账号、当前正式成员和有效 owner 绑定，不恢复已撤销的绑定。若治理依据已损坏，当前接口明确返回冲突，后续所有权治理流程负责修复。
5. 列表不返回负责人实名和联系方式；详情受平台权限保护。治理审计只保存状态、版本和负责人 ID，以及通过既有安全校验的理由。API 与页面均不持久缓存私有数据。

## 备选方案

- 代录时直接激活组织：绕过审核与运营授权边界，不采用。
- 用独立事务调用角色授予服务：可能留下组织已通过但成员/角色或审计不完整的状态，不采用。
- 冻结时批量撤销所有角色、解冻重新建立：会丢失原始授权生命周期并可能恢复已撤销权限，不采用。
- 同期交付完整邀请、成员、所有权转移：扩大治理状态与跨模块协作范围，分期实施。

## 后果

本期提供真实平台治理闭环。用户自助创建、成员审核等已由 ADR 0028、ADR 0032 接续，平台邀请码与所有权移交已由 [ADR 0034](0034-platform-invites-and-ownership-transfer.md) 接续。生产部署前需应用 `0006`；前端继续静态构建，运行时不增加服务或依赖。API 生产构建排除独立 `scripts`，独立脚本仍纳入类型检查并通过自身 CLI 执行。
