# ADR 0027：独立的平台媒体治理入口

- 状态：已接受
- 关联：[FS-0017](../specs/0017-admin-file-management.md)、[ADR 0021](0021-media-control-plane.md)、[ADR 0015](0015-casbin-authorization-engine.md)。

## 背景

管理端需要文件管理，但 ADR 0021 的业务媒体入口仅允许 owner 或真实业务关系，且明确不提供无业务归属的媒体页面。直接扩大 `requireMediaAccess` 会使普通业务端点获得不必要的平台越权能力。

## 决策

- 扩展 ADR 0021 的页面限制：允许独立管理端媒体治理页面，不改变普通媒体端点及上传授权。新增固定 `media.manage` 权限，只允许平台范围的 platform_admin，矩阵仍由 authorization 单点维护。
- 媒体模块拥有管理查询投影与操作，复用媒体表、媒体 Repository、存储端口和事务基础设施，不引入迁移、依赖或桶扫描。元数据查询、详情、下载签发和删除均审计；下载和删除必须提供理由。
- 平台管理员可治理全平台媒体，不借此获取任何组织运营权限。下载独立二阶段授权；留存证据的通用删除禁令同样约束管理员。所有存储 IO 在事务外。
- 页面不提供无用途上传或在线预览；下载仍为 60 秒 attachment/no-store。文件名只作受限元数据展示，不用作 HTML、对象 key 或下载路径。

## 备选方案

沿用 owner 接口无法完成平台治理；给 platform_admin 全面绕过现有媒体业务关系会扩大普通 API 权限；直接浏览 Bucket 缺少业务状态和审计，均不采用。

## 后果

新增明确的跨所有者媒体治理能力，需要严格保护平台管理员账号，并测试实时撤权、二阶段授权、同事务审计及留存限制。短时 URL 已签发后的有效窗口无法即时撤销，沿用 60 秒限制。失败的物理删除可重复提交，不能误报对象已从存储清理。
