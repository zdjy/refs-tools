# ADR 0006：裁判端前端技术栈

- 状态：已接受
- 日期：2026-11-02

## 背景

仓库按 ADR 0001 将裁判端实现为独立静态 SPA，但前端应用目录此前只有包清单，没有 UI 框架、构建工具或应用入口。离线工作台需要明确的交互状态、可测试的规则逻辑及响应式移动端界面，并应保持生产期由 Nginx/CDN 静态托管。

## 决策

裁判端采用 Vue 3 Composition API 与 TypeScript，使用 Vite 和官方 Vue 插件开发、构建，并由 `vue-tsc` 执行 SFC 类型检查。业务计时和会话转换逻辑保持为不依赖 Vue 的纯 TypeScript 模块；SPA 输出为静态文件，不增加生产期 Node.js 前端服务。

## 考虑过的方案

- React + Vite：生态成熟，但与实现者更熟悉 Vue 的偏好不符，没有足以抵消学习与维护成本的产品优势。
- 原生 TypeScript + Vite：依赖更少，但随着比赛工具状态和页面交互增长，需要自行建立组件/响应式抽象。
- Vue 3 + Vite：具备成熟的轻量响应式组件模型，Composition API 适合分离纯领域逻辑，构建产物仍可静态托管。

## 后果

- 应用依赖集中在 `apps/referee-web`，不会改变 API 或其他 workspace 包的运行时。
- 页面组件通过 Vue SFC 构建；定时器、规则及存储序列化仍应保持可独立测试。
- 构建工具只用于开发与 CI 构建，生产主机不运行 Vite 或 Node.js 前端服务。
- SPA 继续复用仓库的 FIBA 暖沙金 UI 基线，页面交互另需满足移动触控、键盘和 reduced-motion 要求。
