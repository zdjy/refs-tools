# ADR 0016：独立管理端与渐进业务接入

- 状态：已接受
- 关联：[FS-0007](../specs/0007-admin-console.md)、ADR 0001、0007、0008、0010、0013、0014

## 背景

需求方要求并行推进管理端。当前 API 只有身份、授权基础和审计查询，不能把组织/认证等尚未实现的接口当作已有能力。ADR 0001 使用 `apps/admin-web`，后续规约以 `apps/referee-admin` 举例；本次采用前者，后者仅为示意而非额外应用。

调研了 [Naive UI Admin](https://github.com/jekip/naive-ui-admin)、[Vue Naive Admin](https://github.com/zclzone/vue-naive-admin)、[SoybeanAdmin](https://github.com/soybeanjs/soybean-admin)。它们的模块导航、布局、错误页面和可定制主题适合参考，但整套引入会带来动态菜单权限、持久化登录状态、UnoCSS 或自动路由等与既有方向不一致的机制。

## 决策

1. 新建独立构建的 `apps/admin-web` 静态 SPA，生产基路径 `/admin/`。复用现有 Vue、TypeScript、Vite、Naive UI、Tailwind、Router、Pinia 版本，不新增后台模板、图表、图标或表格封装框架。
2. 只参考公开项目的交互思想，不复制其源码或图片。沿用共享 FIBA UI 规格；各 SPA 独立拥有主题适配入口，不跨应用导入代码。暂不为两个入口抽象新的 UI 包。
3. 使用显式静态路由、懒加载页面和页面内存状态。只有登录会话由 Pinia 跨路由共享；受保护页面离开后销毁查询状态，不使用 KeepAlive 或默认持久化。
4. Cookie 继续同源 `/api/v1`。不引入 JWT、前端角色图、后台权限探测 API。现有会话 DTO 不含角色；因此登录只代表进入外壳，不表示获得平台权限。受保护业务由真实 API 返回 401/403；导航及待接入流程说明不包含业务数据。
5. 首批真实接入登录、会话恢复、退出与平台审计。其他模块展示接入边界和工作流程，不请求虚构端点，不提供模拟批准/发布按钮，也不显示虚构总数。
6. 管理端首批不注册 Service Worker，不排队离线写操作，不缓存私有 API、凭据或签名 URL。读取失败清空受保护列表，重试需重新授权；401 清空会话并销毁当前业务视图。退出失败不冒充退出成功。
7. 与客户端静态产物一起由现有 Nginx 托管，`/admin/assets/` 指纹资源不可变缓存，`/admin/*` 回退管理端入口。构建在开发/CI 完成，不新增生产前端进程。

## 备选方案

- 完整 fork 模板：起步快，但需删除大量不适合的演示功能与权限机制，后续升级成本高。
- 在裁判端内部加管理路由：减少入口文件，但把两类交互和发布耦合，不符合 ADR 0001。
- 预先制作全量 Mock CRUD：视觉丰富，但容易将不存在的权限、接口和业务闭环当作已完成，本次只在测试边界使用替身。

## 后果

现阶段可验证登录与真实审计闭环，其余业务按 FS-0007 的依赖切片交付。管理端不是上线即具备所有后台能力；管理员初始化仍使用受控部署命令，不开放自助提权。未来角色/能力投影若新增，必须先定义 contracts 并单独评审，不能用读取审计来推断全部权限。
