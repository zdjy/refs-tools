# ADR 0022：管理端用户 CRUD 与 Cookie 会话边界

- 状态：已接受
- 范围：FS-0013 管理端用户 CRUD
- 关联：[FS-0013](../specs/0013-admin-user-management.md)、[ADR 0010](0010-email-auth-and-session-security.md)、[ADR 0014](0014-scoped-authorization-and-audit-foundation.md)、[ADR 0023](0023-alova-http-client-and-ddd-gateway.md)（管理端请求层实现）

## 背景

管理端原有模板使用演示 token 和本地存储用户资料，不能作为真实管理权限依据。用户账号属于身份模块，用户查询和变更又必须遵守实时的平台授权、逻辑删除、会话撤销和追加式审计约束。若把用户资料、密码摘要或授权快照下发到浏览器并持久化，会扩大私有数据暴露面，也会使撤权不能即时生效。

## 决策

1. 管理端保留邮箱密码登录并增加邮箱验证码登录（复用 `login` 用途 challenge，不新增注册入口），两种登录均须在普通认证成功后通过 `/admin/session` 实时校验平台权限，核验失败尝试撤销普通会话且不得应用管理端身份。登录、会话恢复、退出和用户 CRUD 全部调用同源 `/api/v1` API；凭据仅通过 `__Host-refs_session` HttpOnly、Secure、SameSite=Lax Cookie 传递。浏览器内存中的 Pinia 状态只保存当前展示所需的最小身份信息，不把 Cookie、用户列表或详情写入 localStorage。
2. 管理端用户接口由身份模块提供最小投影，只返回用户 ID、邮箱、显示名称、邮箱验证状态、账号状态、创建时间、版本及当前平台角色；密码摘要、会话、手机号和业务档案不属于该投影。邮箱仍由创建流程规范化并由数据库唯一约束兜底，编辑不可修改邮箱。
3. 用户新增、资料/状态更新和逻辑删除使用 `AdminUsersService` 的事务端口。平台管理员权限从当前 Cookie 会话和事务内的实时 role binding 解析，业务变化与最小审计在同一事务提交；密码使用已有有界异步 scrypt，KDF 在事务外执行，写入前重新授权。
4. 更新使用 `version` 条件写入避免陈旧表单覆盖；停用和删除撤销该账号所有会话，恢复账号不恢复旧会话。删除仅写入 `deleted_at` 并停用账号，保留邮箱和历史认证、业务记录及审计。
5. 当前操作者、有效平台管理员和组织所有者不可被管理端停用或删除；角色变更与组织所有权移交由各自业务模块处理。本模块不提供角色 CRUD、菜单授权、自定义角色或批量删除。

## 备选方案

- **继续使用模板 token 和 localStorage**：无法满足服务端实时撤权和私有数据边界，拒绝。
- **JWT 或前端角色快照作为管理权限**：不能可靠支持会话撤销和数据库绑定即时生效，拒绝。
- **将密码重置交给管理端用户 CRUD**：扩大高风险操作范围；本期仅允许创建初始密码，后续邮箱验证和密码流程仍由认证模块负责，拒绝。

## 后果

- 静态管理端必须与 API 同源 HTTPS 部署，并按认证配置校验 Origin；API 仍是唯一授权边界。
- 管理端首次进入非登录页需要调用会话接口；失败时回登录页，网络错误不会被伪装为空列表。
- 组织扩展、角色授予/撤销及平台管理员初始化继续遵循既有身份与授权 ADR，不在本模块复制策略。
