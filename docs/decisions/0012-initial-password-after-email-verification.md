# ADR 0012：邮箱验证后首次设置密码免重复验证

- 状态：已接受
- 范围：修订 ADR 0010 中密码设置一律要求 password challenge 的边界；已有密码的修改策略不变。

## 背景

邮箱验证码注册已经验证邮箱并建立安全会话，但账号页将首次设置和修改已有密码混为同一流程，导致新用户需要再次收取验证码。产品要求注册后可直接设置首次密码；原规格与 ADR 0010 的一律重验条款需要明确窄范围例外。

## 决策

- 仅对有效会话、邮箱已验证且数据库中尚无密码的账号，允许通过 `{newPassword}` 首次设置密码，不重复签发验证码。账号和会话仍在验证码注册成功时建立，密码保持可选，不增加“待完成注册”状态或持久化前端凭据。
- 会话响应新增 `user.hasPassword`，供账号页展示首次设置或更换密码。该投影不作为授权依据；不暴露哈希、不接受客户端声明密码状态或目标用户。
- 首次设置与已有密码修改共用账号行锁，在事务内重验会话和当前密码状态。已有密码的修改仍要求本人邮箱的 password 用途一次性 challenge，禁止通过省略 proof 降级。
- 继续复用现有密码强度、异步有界 scrypt、同源 Origin、Secure HttpOnly Cookie 和会话轮换策略。首次设置成功同样撤销全部旧会话并签发新会话；不新增依赖或数据库迁移。

## 备选方案与后果

- 在前端复用注册验证码：验证码已一次性消费，不可跨用途重放，拒绝此方案。
- 只在前端隐藏验证码框：无法满足后端授权且容易出现安全绕过，拒绝此方案。
- 新增短时首次设置 token 或会话用途字段：能进一步收窄首次设置窗口，但会增加状态、迁移和恢复复杂度；当前邮箱已验证且无密码的账号本来就可验证码登录，采用既有安全会话边界。
- 无密码且邮箱已验证的有效会话被窃取时可能被用于绑定首次密码；这是本例外的边界，因此保留既有 Cookie、同源校验和可撤销会话保护。有密码的账号不受该例外影响。
- 刷新或后续验证码登录后仍可继续首次设置；弱密码失败不消耗首次设置资格。通过 Service、HTTP、前端状态测试及独立 PostgreSQL 并发测试验证。用户可见行为及验收维护在 [FS-0002 身份与账号](../specs/0002-mvp-platform-feature.md#32-身份与账号)。
