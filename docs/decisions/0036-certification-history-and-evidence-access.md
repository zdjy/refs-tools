# ADR 0036：认证历史、实时效力与原件范围授权

- 状态：已接受
- 关联：[FS-0030](../specs/0030-certification-api.md)、[FS-0001 §7](../specs/0001-mvp-scope-and-business-rules.md#7-认证与资质)、[ADR 0021](0021-media-control-plane.md)、[ADR 0027](0027-admin-media-governance.md)、[ADR 0015](0015-casbin-authorization-engine.md)。
- 替代范围：ADR 0027 的全平台媒体下载能力不再包含认证原件；其他用途和元数据治理不变。

## 背景

认证需要保留材料及人工决定历史，同时依据组织与成员现状立即暂停效力。FS-0002 的申诉接口写返回 `appeal_pending`，但 FS-0001 要求申诉期间原认证状态不变。通用平台文件下载能力还会绕过认证原件的审核范围要求。

## 决策

1. 每个用户、认证范围保留一个当前聚合；独立的 `certification_history` 保存每次变更的完整材料快照，`certification_media` 保存不可变历史关联。当前查询和分页摘要分别投影，不在普通列表返回证书字段。迁移为 `0011`，不引入依赖。
2. `status` 表示人工决定，`effectiveStatus` 根据当前组织与成员状态派生。退出、移除和冻结使已批准组织认证的当前效力为 `suspended`；重新入会或解冻恢复其效力，不改写历史、不恢复人工暂停或撤销。待审组织申请在成员或组织失效时不能继续审核。
3. 申诉独立保存 `pending/decided`，不以 `appeal_pending` 覆盖认证。创建、补件、提交、审核与申诉都有幂等键或版本前置条件；待处理申诉阻止普通决定。组织复核由当前 owner 承担，平台复核由另一位平台管理员承担，均不得为申请人或原审核人。负责人兼任原审核人时须先通过现有治理流程变更负责人，本轮不引入指定复核员分配模型。
4. 组织认证用例先锁组织，后按账号 ID 排序锁账号，再锁认证。平台创建及提交先按 ID 锁定已存在的推荐组织，资格查询限定在这些已锁组织内，避免后续发现新组织时反向加锁。平台资格在创建及提交时检查；既有平台认证不因推荐组织认证撤销而自动撤销。
5. 认证原件使用专用申请/申诉入口，核对实际关联、用途、对象状态和当前权限。申请人可读本人历史；组织认证员仅能读取本组织认证材料，平台审核员仅能读取平台申请材料；组织申诉原件要求 owner 且回避原审核人。材料不跨认证范围复用，避免通过另一申请扩大原件读者。
6. 通用管理媒体入口拒绝签发认证原件链接，元数据仍可治理；本人通用媒体入口保持既有归属约束。专用入口在事务外签发 60 秒链接，返回前另一个短事务重验权限并写审计。审计失败或中途撤权不返回链接，不保存或记录签名 URL。
7. 当前记录、历史、材料关联、申诉和审计使用同一事务。认证历史和材料关联禁止 UPDATE/DELETE/TRUNCATE。材料字节仍由浏览器与私有对象存储直接传输，API 不代理。

## 备选方案

- 退出时批量覆盖认证状态：需要保存恢复原因并协调所有成员写路径，容易把人工暂停当成自动暂停恢复，未采用。
- 将申诉直接作为认证状态：会掩盖原决定或错误恢复效力，未采用。
- 沿用平台通用下载认证原件：违反认证审核范围，未采用。
- 完整 Event Sourcing 或新增授权服务：本轮无重放或独立服务需求，未采用。

## 后果

需同时读取 `status/effectiveStatus`；历史快照中的效力表示写入当时，不代表当前资格。独立申诉与更严格的原件入口需要前端后续适配。旧管理端认证原件下载会返回明确错误，须引导至认证申请入口。已签链接在 TTL 内仍可能有效。运行账号必须增加认证表的精确权限，不能给历史表修改权限。
