# ADR 0035：成员联系方式的按用途投影

- 状态：已接受
- 范围：[FS-0029](../specs/0029-member-contact-projection.md)
- 关联：[ADR 0028](0028-organization-members-and-invitations.md)、[FS-0016](../specs/0016-organization-membership.md)、[FS-0023](../specs/0023-account-profile-settings.md)

## 背景

ADR 0028 将成员列表限制为昵称、标识、状态与时间，不返回邮箱、实名或联系方式；FS-0023 同时规定真实姓名、手机号、详细地址和出生日期只返回给本人，后续业务按用途另行投影，不复用整份档案。成员管理者在审核入会、核对身份或联络成员时确实需要其中一部分资料，直接在列表响应里追加字段会扩大每次翻页的暴露面，也会把“成员列表”和“联络资料”混成一个用途。

## 决策

1. 新增独立的读接口 `GET /organizations/:id/memberships/:recordId/contact`，只在成员管理者打开详情时按需读取，不扩展成员列表或邀请列表。
2. 投影只包含完成联络与身份核对所需的字段：昵称、头像媒体 ID、真实姓名、手机号、地区展示文本。登录邮箱、详细地址、出生日期和任何凭据不进入该投影。
3. 权限沿用组织成员管理能力 `organization.members.manage`，即负责人与组织者；平台管理员的 `platform.manage` 不隐含该权限。跨组织记录与无权请求统一返回 `404`，不泄露记录是否存在。
4. 历史成员关系（已退出、已移除、已驳回）仍可读取，因为这些记录本就属于该组织的成员管理历史，管理者此前已能看到其名单；如后续业务要求只保留当前关系，可收紧到 `pending/active`，无需改变响应形状。
5. 每次成功读取写入 `membership.contact_viewed` 审计，快照为空，不保存联系方式；审计写入失败时整笔读取失败。签名头像 URL 只在浏览器内存中短暂存在。
6. 页面默认遮蔽手机号，管理者主动展开后才显示整串；这不是服务端授权，而是降低肩窥与截图泄露的展示约束。

## 备选方案与后果

- 在成员列表响应中追加联系方式：拒绝。每次翻页都会传输并可能被缓存敏感字段，暴露面与用途都不匹配。
- 复用 `GET /profile` 并传入 `userId`：拒绝。该端点只接受本人会话身份，放开会破坏 FS-0023 的隐私边界。
- 允许平台管理员直接读取：拒绝。本次需求属于组织成员管理；平台治理需要单独的产品决策与入口。
- 不写读取审计：拒绝。联系方式属于受限资料，成员读取已有“读取与写入都审计”的既有约束，详情读取也应留痕。
- 返回完整档案后由前端隐藏：拒绝。未展示的字段不应传输到浏览器。

后果：新增一条契约、一个只读接口与一个审计动作；成员列表的既有投影保持不变。手机号未接短信验证，仍只作为联络信息使用，不用于登录或身份核验。用户端详情弹窗与后端投影需同步演进，新增字段必须先更新本 ADR 与 FS-0029。
