# ADR 0015：采用 Casbin 作为服务端授权引擎

- 状态：已接受
- 关联：[ADR 0003](0003-scoped-rbac-and-assignment-workflow.md)、[ADR 0014](0014-scoped-authorization-and-audit-foundation.md)
- 替代范围：ADR 0014 第 3 项的完整纯 domain policy 实现及第 9 项不新增第三方库的限制；其余实时授权、事务和审计决定继续有效。

## 背景

需求方确认允许新增第三方依赖，并选择 Node-Casbin 替换自研的角色到权限匹配。现有授权还依赖资源真实归属、成员现状、有效期、所有权和业务状态；引入库不能退化为全局角色快照，也不能改变平台与组织边界。生产仍为 2 CPU、2 GB 主机。

## 决策

1. 仅 `apps/api` 直接依赖 `casbin`。不引入独立授权服务、数据库 adapter、Watcher、ORM 或新的角色存储；`role_bindings` 仍是唯一角色绑定事实源，无需数据库迁移。`contracts` 与 `domain` 不依赖 Casbin。
2. 将角色、权限与目标资源种类的固定矩阵移至 authorization 模块，作为唯一授权策略源。Casbin 模型以角色、绑定作用域、服务端资源和权限作为请求，精确匹配角色/权限/目标种类，并通过纯作用域函数匹配组织 → 赛事 → 比赛归属。没有超级用户通配符，不使用跨绑定角色继承。
3. `packages/domain` 仅保留权限词汇及可独立测试的领域约束：角色允许范围、当前所有权、组织/资源状态、成员有效性、绑定生效/过期/撤销及归属覆盖。不再保留独立的角色授权矩阵或完整自研决策引擎。self 权限由当前用户及资源所有权派生，通过内部 self 策略判断，不写入角色绑定。
4. Casbin 适配器位于 API 基础设施，通过无库类型的 `PermissionEvaluator` 端口注入应用服务。装配入口在接收请求前建立一个固定策略 Enforcer，失败则启动失败；固定策略在进程内只读，不对外暴露管理接口，不执行策略持久化。运行期使用同步匹配，事务内无文件或网络 IO。
5. Enforcer 不保存用户绑定、成员状态、资源对象或授权结果。每次请求仍在调用者同一事务内重新读取并锁定授权依据；每条有效绑定独立提交 Casbin 判断，不能用一个绑定的角色和另一个绑定的范围拼接授权。引擎异常向统一错误边界传播，不回退放行或启用旧引擎。
6. 修改固定策略通过代码评审、测试、构建和重新部署生效。数据库绑定的授予、撤销、成员退出及组织冻结仍实时生效，不需要重启或刷新策略。保留现有 Cookie 会话、403/404 语义及同事务审计，不新增公开授权探测接口。

统一实施边界及自检仅维护在[后端规约](../agents/coding-standards/backend.md#4-授权引擎与策略边界)和[执行协议](../agents/coding-standards/workflow.md)。

## 备选方案

- **继续自研全部 policy**：无新增依赖，但角色/权限匹配仍由项目自行维护，未采用。
- **CASL**：适合资源条件 Ability；当前以固定角色及显式绑定范围为主，需求方选择 Casbin。
- **Casbin 数据库策略表、共享可变角色图或 CachedEnforcer**：会引入第二事实源、事务外状态或过期授权风险，当前没有必要。
- **将 Casbin 放入 domain**：违反共享纯领域包的依赖边界，且使客户端承担服务端授权依赖，未采用。

## 后果与验证

- 增加 API 运行时依赖和少量固定策略初始化开销，但不增加进程、数据库连接或用户规模相关的进程内角色图；前端不包含 Casbin。
- 授权服务、审计查询及内部角色授予/撤销必须共享注入的 evaluator；未来业务写入仍显式复用自己的事务，不在授权后另开事务。
- 快测验证完整角色/权限/目标矩阵、跨作用域、多绑定不拼接、self、未知权限默认拒绝、异常不回退和不同请求状态不串扰。真实 PostgreSQL 套件继续验证锁、撤权、归属解析及审计原子性，不能用引擎单测代替数据库验收。
- 新增依赖后执行快测、类型检查和生产构建，并检查单测内存预算；不得将依赖体积或资源消耗未经测量描述为零。
