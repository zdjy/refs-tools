# ADR 0008：裁判端客户端状态管理与路由

- 状态：已接受
- 日期：2026-11-03

## 背景

裁判端当前只有离线工作台，但 MVP 规格包含学习、考试、认证、组织和赛事等多个页面流程。根组件直接挂载工作台，无法提供可复制/刷新的页面 URL，也缺少统一的未知路径处理。工作台状态由页面 Composable 管理，下一阶段的登录身份和跨页面上下文也需要明确状态所有权。

## 决策

1. 裁判端采用 Pinia 管理确需跨组件/路由共享的客户端状态。当前工作台作为首个 Pinia store；其业务状态逻辑仍保留在可注入存储 ports 的纯页面状态工厂中，以保持业务逻辑可独立测试。
2. Pinia 不自动持久化状态。工作台继续使用既有 `localStorage` 存储适配和版本协议；认证凭据、服务器数据及私有业务记录不得因采用 Pinia 而默认持久化。
3. 裁判端采用 Vue Router HTML5 history 和显式静态路由表。页面组件使用动态 import 做代码分割；此处的动态 import 不等于根据用户角色从服务端生成路由。
4. 路由元信息和导航守卫只用于导航体验。所有受保护资源和操作仍由 API 按当前用户、作用域、资源及业务状态独立授权；前端角色/菜单检查不构成安全边界。
5. 未知路径展示 404 页面，根路径重定向至工作台。部署环境须将 SPA 路径回退到 `index.html`。

## 考虑过的方案

- 继续使用局部 Composable 并自行维护地址切换：当前业务规模小，但重复实现历史导航、深链接和 404，且难以支撑规格中的多个独立页面。
- 自动按文件扫描生成路由或根据后端菜单动态添加角色路由：当前没有运行时插件需求，会引入额外复杂度；授权和路由菜单也不应绑定为同一安全机制。
- Pinia 持久化所有状态：会混淆服务器权威数据与 UI 状态，并增加敏感数据落入不安全持久缓存的风险。

## 后果

- 视图经 router-view 装配，页面可以使用稳定 URL；未知路径有一致反馈。
- 工作台状态由 Pinia 实例统一拥有；本地存储协议、故障提示、删除和导出行为保持现有实现。
- 新业务 store 仅在跨组件/路由共享有明确需求时创建；页面局部状态仍留在页面 Composable。
- Nginx/CDN 部署需配置 history fallback；发布配置应同步检查直接访问子路径和刷新行为。
- Pinia 与 Vue Router 作为裁判端应用级依赖，不进入 contracts、domain 或 API。
