# ADR 0037：认证审核的最小身份投影与记录查询

- 状态：已接受
- 关联：[FS-0032](../specs/0032-certification-operations.md)、[ADR 0036](0036-certification-history-and-evidence-access.md)、[ADR 0035](0035-member-contact-projection.md)。

## 背景

审核队列仅有账号标识，审核人难以与证书原件比对。用户确认需要实名、昵称、账号标识，并要求可查询已批准/已暂停认证，执行现有暂停、恢复、撤销规则。原有待审队列不能承载已办记录。

## 决策

1. 新增独立 `CertificationReviewSummary` 投影，仅增加申请人的当前昵称及可空实名。投影由认证模块拥有，跨模块只读 `users.display_name` 与 `referee_profiles.legal_name`；不返回手机、邮箱、生日、地址或完整个人档案。
2. 本人摘要、当前认证聚合与不可变历史保持原契约。身份是本次查询时的资料，不写入认证决定或历史快照；实名未填写时如实显示，不改变申请资格。
3. 审核队列与记录查询先在同事务内实时校验现有范围权限，读取后追加最小审计，审计失败不返回结果。组织负责人复核身份不授予普通认证记录查询权限，平台权限不覆盖组织范围。
4. 组织与平台分别增加认证记录分页查询，支持人工状态筛选，排除草稿，稳定沿用创建时间与 ID 全序。待审队列仍只承载当前可审核申请。
5. 所有私有响应保持 no-store；身份只留页面内存。未新增数据表、角色、权限矩阵、持久化缓存或基础设施。

## 备选方案

- 复用个人档案接口或组织联系方式接口：返回范围及用途不匹配，未采用。
- 把身份字段放入认证聚合：会混淆当前档案与申请快照，扩大历史留存，未采用。
- 只从待审队列进入详情：无法再次找到已批准/暂停记录，未采用。

## 后果

审核队列响应增加用途明确的身份字段，读取必须审计。客户端与 API 需一起部署；生产 API 运行账号需具备档案字段的读取权限。实名可空，审核人仍应核对材料，不能将昵称当作法定身份。
