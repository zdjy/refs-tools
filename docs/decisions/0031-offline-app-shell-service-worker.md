# ADR 0031：离线应用外壳 Service Worker

- 状态：已接受
- 关联：[ADR 0008](./0008-client-state-and-routing.md)、[ADR 0030](./0030-network-resilience-and-loading-feedback.md)、[FS-0003](../specs/0003-team-scorer-console.md)、[FS-0006](../specs/0006-home-navigation.md)

## 背景

根级 `AGENTS.md` 要求裁判端是可安装、可离线的 PWA，并要求明确缓存范围。此前仅有 manifest，没有 Service Worker：已加载的页面可继续操作，但场馆信号差时刷新、冷启动或从后台被回收后重新打开，会直接失败。本地工作台的数据本来就存在浏览器本地，却因为取不到页面代码而无法使用。

FS-0002、FS-0003、FS-0006 曾约定"不新增 Service Worker"，那是当时只做本地工具、避免过早引入缓存的阶段性范围，与 `AGENTS.md` 的最终要求不一致。本 ADR 取代这些阶段性约定，范围只限应用外壳。

## 决策

1. **只缓存同源静态外壳**：构建产物中的 `js`、`css`、`html`、`png`、`ico`、`webmanifest` 以及 `public/` 下的图标，全部预缓存，首次联网后所有路由都可离线打开。
2. **不拦截私有请求**：非 GET、跨域、`/api/`、`/admin` 一律不进入 Service Worker，因此不缓存私有 API 响应、认证状态或对象存储签名 URL。
3. **三条策略**：
   - 导航请求网络优先，最多等待 4 秒，超时或失败用缓存的 `/` 外壳兜底（SPA 路由由前端解析）。
   - `/assets/` 下带内容哈希的资源缓存优先。
   - 版本号取预缓存文件名集合的哈希；激活时只删除 `referee-shell-` 前缀的旧缓存。
4. **更新由用户确认**：不调用 `skipWaiting`。新版本安装完成后显示"有新版本可用"，用户确认后才接管并重载一次。比赛进行中不被意外重载；提示明确说明已保存的记录不受影响、撤销历史会清空。
5. **有界缓存**：构建时统计预缓存总量，超过 2.5 MB 构建失败，避免外壳在无人察觉时变大。当前约 1.4 MB（gzip 前）。
6. **自写模板，不引入 workbox 或 `vite-plugin-pwa`**：策略只有三条，自写的构建插件加 100 行以内的模板更小、更易审计，符合"不为小需求引入重依赖"的预算约束。
7. **仅生产构建注册**，开发服务器不注册，避免旧模块缓存干扰热更新。

## 备选方案

- **`vite-plugin-pwa` + workbox**：功能完整，但引入较大依赖与生成代码，当前需求用不到运行期路由、后台同步等能力。
- **仅运行期缓存（不预缓存）**：首次访问某路由后才能离线，冷启动时多数分包仍缺失，无法兑现场边可用。
- **`skipWaiting` 自动接管**：更新最快，但可能在比赛进行中重载页面，不可接受。

## 后果

- 首次联网访问会多下载全部分包，约 1.4 MB 未压缩；之后离线可用。
- 前端未登录也能离线打开外壳，但需要网络的功能（登录、社区数据）仍按 ADR 0030 提示离线，不伪装成可用。
- 部署时 `sw.js` 不带版本号，现有 nginx 的兜底规则已对其返回 `Cache-Control: no-cache`，浏览器每次回源校验，无需单独配置。
- 本 ADR 不引入离线写队列；写操作离线时仍按 ADR 0030 拒绝并保留输入。
- 缓存的外壳不含私有数据；共享设备上的本地比赛数据仍按 FS-0003 的共享设备提示处理。
- 浏览器验证：生产预览中注册后预缓存 48 个文件、无 `/api/` 条目；停止服务器后重载 `/workbench`，页面由缓存完整加载。真机弱网与实际安装未验证。
