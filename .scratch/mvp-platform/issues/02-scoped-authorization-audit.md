# 02: 作用域权限与审计

**What to build:** 用户对平台、组织、赛事和比赛资源的访问由服务端按当前角色、作用域和资源状态决定；敏感业务操作可追溯。

**Blocked by:** 01: 邮箱登录与会话

**Status:** implemented

- [x] 受保护资源默认拒绝，本次 API 每次查询执行对象级和作用域授权，并提供后续写用例的事务内授权入口。
- [x] 跨组织访问和已撤销权限的请求被拒绝，不因旧会话声明继续授权。
- [x] 提供高风险操作的同事务追加审计基础；本次角色授予/撤销及审计查询已接入，其余随所属业务任务接入。
- [x] 审计使用安全投影，拒绝敏感字段、明显凭据和 URL；业务用户不能修改、删除或清空记录。

## Comments

- Task 4 已实现。需求方确认提前建立组织/成员/赛事/比赛最小归属骨架，Task 7/15 用新增迁移扩展；未提前交付这些模块的业务接口。
- 提供纯权限 policy、实时 scope resolver、内部角色授予/撤销、同事务审计 writer，以及平台/组织审计 GET 接口；不提供公开审计写入或任意权限探测接口。
- 冻结组织只读历史审计，退出组织/撤权后同一 Cookie 的下一请求立即失权；平台身份不自动代行组织所有者或组织者。
- 实施依据和接入边界见 `docs/decisions/0014-scoped-authorization-and-audit-foundation.md`；最小权限部署和测试账号要求见 `apps/api/db/AUTHORIZATION_AUDIT.md`。
- 全量快测 126 项、PostgreSQL 集成 32 项、workspace typecheck/build 与生产镜像 smoke 通过；快测在小于 300 MB 的容器限额下通过，cgroup 内存峰值 220,291,072 字节。完整业务状态机、自审回避、考试范围和媒体授权仍随后续业务任务验收。
