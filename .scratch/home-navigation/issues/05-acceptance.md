## 实施步骤

1. 对照 A01～A08 补齐测试；运行 `pnpm test`、`pnpm typecheck`、前端 `build`、`test:styles` 和 `git diff --check`。
2. 按项目既有低内存测试流程检查单测资源，不把浏览器测试并入低内存单测进程。
3. 比较本次实施前后 CSS、JS 及逐文件 gzip 汇总体积；查看构建 chunk，验证首页没有同步引入完整工作台和未来业务模块。
4. 按 B01～B09 检查浏览器，覆盖真实点击、子路径刷新、全部指定宽度、断点前后、横屏、键盘、焦点和 reduced-motion。
5. 使用本地合成身份响应覆盖加载、401、成功、失败及重试，不在仓库保存 Cookie 或真实身份数据。
6. 验证工作台运行中往返、保存失败后往返、重试、导出；同时回归新建、换节、统计及认证相关现有流程。
7. 通过 README 的 HTTPS Compose 入口验证 Nginx history fallback 和认证；不能执行时记录原因，不用 Vite 检查冒充完整联调。
8. 在 FS-0006 追加验证记录，更新所有 ticket 的 Status 和实际完成项；只把真实完成的检查标为通过。
